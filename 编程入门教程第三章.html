第 1 小节

什么是数据结构

摆放数据的规矩

到第 2 章为止，我们已经用过两种装数据的方式： 数组（列表）按编号排成一排，字典按名字各就各位。 其实它们都属于同一个家族——数据结构。

🔑 定义

数据结构，就是摆放数据的规矩。 规矩不同，放数据、找数据、删数据的方式就不同，擅长的场景也不同。

一个贴近的例子：把书放进书架中的不同格子里，按编号/类型/发行日期/颜色标签/文字标签/名字摆放，有很多种不同的摆放方法。 摆放方式不同，找书的方法就完全不同。数据也是一样—— 先想清楚你打算怎么用它，再决定按什么规矩摆。

本章要认识的成员

栈

只在一头放、同一头拿。最后放的，最先拿到。

队列

一头进、另一头出。先来的，先被服务。

链表

格子不必挨着坐，每个格子记着下一个在哪。

哈希表（字典）

按名字直接算出位置，不用一排排翻。

树

一个起点，一层一层往下分叉。

图

若干个点，任意两点之间都可以连线。

它们之间没有绝对的优劣，只有是否合适。 选择数据结构时只需要回答一个问题：我最常对它做什么操作？ 接下来的每个小节，我们就按这个思路逐个认识它们。

本章专业术语较多，但是本章的学习目标并不是完全掌握这些数据结构，而是理解它们的特点和适用场景。你只需要知道“原来数据还可以这样排”就可以了，似懂非懂没有关系

🔑 第 1 小节小结

1. 数据结构 = 摆放数据的规矩，数组和字典都是其中一员。

2. 规矩决定操作方式：怎么放、怎么找、怎么删。

3. 选结构的依据：你最常对它做什么操作。

第 2 小节

栈：最后放的，最先拿

后进先出（LIFO）

栈的规矩只有一条：只能在一头放东西，也只能在同一头拿东西。 这一头叫做「栈顶」。

想象桌上的一摞盘子：新盘子总是放在最上面，拿走时也总是从最上面拿。 最先放下的那只盘子，压在最底下，最后才被拿到。 所以栈的顺序是四个字——后进先出。

栈只有两个基本操作：

push（入栈）

把一个东西放到栈顶。

pop（出栈）

把栈顶的东西拿下来。

看一个完整的例子——用栈记录操作历史，模拟「撤销」功能：

#include <iostream>
#include <stack>
#include <string>
using namespace std;

int main() {
    stack<string> history;

    history.push("打开文档");   // 入栈：记录每一步操作
    history.push("输入标题");
    history.push("插入图片");

    cout << history.top() << "\n";  // top：看一眼栈顶（不拿走）
    history.pop();                  // 出栈：撤销最近的一步
    cout << history.top();
    return 0;
}
history = []              # Python 里用列表当栈：列表末尾就是栈顶

history.append("打开文档")  # 入栈：记录每一步操作
history.append("输入标题")
history.append("插入图片")

print(history[-1])        # 问问AI这里的-1是什么意思
history.pop()             # 出栈：撤销最近的一步
print(history[-1])
▶ 运行结果
插入图片
输入标题

「插入图片」是最后放进去的，所以最先被拿到、最先被撤销。 编辑器里的 Ctrl+Z、浏览器的「后退」按钮，背后都是这个规矩。

💡 什么时候用栈

凡是需要「最近发生的先处理」的场景：撤销功能、页面后退、检查括号是否配对。

小试牛刀：依次 push 10、20、30，然后 pop 一次，拿到的是几？
🔑 第 2 小节小结

1. 栈只在一头（栈顶）放和拿，顺序是后进先出。

2. 两个操作：push 放上去，pop 拿下来。

3. 适合「最近发生的先处理」：撤销、后退、括号配对。

第 3 小节

队列：先来的，先被服务

先进先出（FIFO）

队列的规矩和栈正好互补：从一头进（队尾），从另一头出（队头）。

这就是生活中排队的规矩：新来的人站到队尾，队伍最前面的人先接受服务。 谁先到，谁先被处理，所以队列的顺序是——先进先出。

看一个例子：打印店按收到的顺序处理打印任务。

#include <iostream>
#include <queue>
#include <string>
using namespace std;

int main() {
    queue<string> tasks;

    tasks.push("打印简历");     // 入队：任务排到队尾
    tasks.push("打印试卷");
    tasks.push("打印照片");

    cout << tasks.front() << "\n";  // front：队头的任务
    tasks.pop();                    // 出队：处理完队头的任务
    cout << tasks.front();
    return 0;
}
from collections import deque   # 借用双端队列工具

tasks = deque()

tasks.append("打印简历")   # 入队：任务排到队尾
tasks.append("打印试卷")
tasks.append("打印照片")

print(tasks[0])           # 看一看队头的任务
tasks.popleft()           # 出队：处理完队头的任务
print(tasks[0])
▶ 运行结果
打印简历
打印试卷

「打印简历」最先进队，所以最先被处理。如果换成栈， 最后来的「打印照片」反而会插队到最前面——这显然不公平。

栈和队列，一对互补的规矩

栈

同一头进、同一头出。
后进先出：撤销、后退。

队列

一头进、另一头出。
先进先出：任务排队、消息缓冲。

小试牛刀：打印任务依次入队 A、B、C，处理（出队）两个任务后，下一个处理的是谁？
🔑 第 3 小节小结

1. 队列一头进、一头出，顺序是先进先出。

2. 入队排到队尾，出队从队头处理。

3. 适合「按到达顺序处理」：任务排队、消息缓冲。

第 4 小节

链表：格子不用挨着坐

每个格子记着下一个在哪

数组的格子是挨着坐的：一排连续的位置，按下标直接跳过去拿。 这带来一个麻烦——要在中间插入一个格子，后面所有格子都得往后挪一个位置。

链表有很多种，这里以其中一种为例——单向链表。

链表换了一个思路：格子不用挨着坐。 每个格子里除了数据，还多放一张纸条，上面写着「下一个格子在哪里」。 从第一个格子出发，顺着纸条就能走完一整排。

用代码把一个三个格子的链条搭出来看看：

#include <iostream>
#include <string>
using namespace std;

struct Node {      // 一个格子：数据 + 纸条
    string data;
    Node* next;    // 纸条：下一个格子的地址
};

int main() {
    Node a{"打开文档", nullptr};
    Node b{"输入标题", nullptr};
    Node c{"插入图片", nullptr};

    a.next = &b;   // a 的纸条指向 b
    b.next = &c;   // b 的纸条指向 c

    for (Node* p = &a; p != nullptr; p = p->next) {
        cout << p->data << "\n";   // 顺着纸条走一整排
    }
    return 0;
}
a = {"data": "打开文档", "next": None}   # 一个格子：数据 + 纸条
b = {"data": "输入标题", "next": None}
c = {"data": "插入图片", "next": None}

a["next"] = b   # a 的纸条指向 b
b["next"] = c   # b 的纸条指向 c

p = a
while p is not None:      # 顺着纸条走一整排
    print(p["data"])
    p = p["next"]
▶ 运行结果
打开文档
输入标题
插入图片

链表换来了什么，付出了什么

得到的好处

在中间插入或删除一个格子，只需要改动旁边两张纸条， 其他格子原地不动。

付出的代价

找第 5 个格子必须从头顺着纸条走 5 步， 不能像数组那样按下标直接跳过去。

💡 数组还是链表

经常按下标找数据 → 数组；经常在中间插入、删除 → 链表。 还是那句话：先看自己最常做什么操作。

小试牛刀：在链表的 a 和 b 中间插入一个新格子 x，需要改动什么？
🔑 第 4 小节小结

1. 链表的格子不必连续，每个格子用纸条记着下一个的位置。

2. 中间插入、删除只需改纸条，不用挪动其他格子。

3. 代价是找第 k 个格子必须从头顺着走，不如数组快。

第 5 小节

哈希表与集合

按名字直接找，只看在不在

哈希表：不用一排排翻

第 2 章用过的字典，内部就是一张哈希表。 它的办法很直接：拿到一个名字（键），立刻用一个固定的算法 算出这个格子的大概位置，直接跳过去，而不是从第一个格子开始翻。

这就是为什么查通讯录很快：哪怕存了一万个联系人， 查「小明」也几乎一步到位。这个换算过程叫做「哈希」， 名字经过换算得到的位置叫做「哈希值」。细节不用深究，记住效果就好： 按名字找东西，哈希表非常快。 

#include <iostream>
#include <unordered_map>
#include <string>
using namespace std;

int main() {
    unordered_map<string, string> phone;

    phone["小明"] = "13800000001";   // 存：名字 → 号码
    phone["小红"] = "13800000002";

    cout << phone["小明"] << "\n";       // 按名字直接取

    if (phone.count("小刚")) {       // count：这个名字在不在
        cout << phone["小刚"];
    } else {
        cout << "通讯录里没有小刚";
    }
    return 0;
}
phone = {"小明": "13800000001", "小红": "13800000002"}

print(phone["小明"])       # 按名字直接取

if "小刚" in phone:       # 这个名字在不在
    print(phone["小刚"])
else:
    print("通讯录里没有小刚")
▶ 运行结果
13800000001
通讯录里没有小刚

集合：只关心「在不在」

集合是哈希表的简化版：只存名字，不存对应的东西。 它只回答一个问题——「在不在」。而且同一个名字存两次，集合里也只会留一份， 也就是自动去重。

一个典型的用法是签到名单：重复签到不算，还能随时查某个人到没到。

#include <iostream>
#include <unordered_set>
#include <string>
using namespace std;

int main() {
    unordered_set<string> signed_in;

    signed_in.insert("小明");
    signed_in.insert("小红");
    signed_in.insert("小明");        // 重复签到：不会多算

    cout << signed_in.size() << "\n";           // 实际到场人数
    cout << signed_in.count("小明") << "\n";    // 1 表示到了
    cout << signed_in.count("小刚");            // 0 表示没到
    return 0;
}
signed_in = {"小明", "小红"}   # 集合：用花括号，但不带键值对

signed_in.add("小明")        # 重复签到：不会多算

print(len(signed_in))       # 实际到场人数
print("小明" in signed_in)  # True：到了
print("小刚" in signed_in)  # False：没到
▶ 运行结果
2
1
0
2
True
False
用哈希表（字典）

需要按名字找到对应的东西：通讯录、商品价格、用户资料。

用集合

只关心「在不在」，或者需要去重：签到名单、已读标记、标签去重。

小试牛刀：往空集合里依次放入 1、2、2、3、3、3，集合里有几个数？
🔑 第 5 小节小结

1. 哈希表把名字换算成位置，按名字查东西几乎一步到位。

2. 集合只回答「在不在」，并且自动去重。

3. 按名字找内容用哈希表；只查在不在、要去重用集合。

第 6 小节

树：一层一层往下分

根、父、子、叶子

前面几种结构装的都是「一排」或「一堆」东西。 但有些数据天生是分层的：电脑里的文件夹一层套一层， 家族谱一代接一代，公司一个部门管几个小组。 这种一层一层往下分的规矩，叫做树。

树的规矩有两条：

规矩一

只有一个起点，叫做根，所有格子都从它往下分。

规矩二

每个格子可以分出几个孩子，但不能绕圈——孩子不能再指回长辈。

树上的格子叫节点。分出自己的节点叫父节点， 被分出来的叫子节点；没有孩子的节点叫叶子。

用代码表示一个小小的文件夹树，并一层一层打印出来：

#include <iostream>
#include <string>
#include <vector>
using namespace std;

struct Node {                  // 一个节点：名字 + 若干孩子
    string name;
    vector<Node*> children;
};

void printTree(Node* node, int depth) {
    cout << string(depth * 2, ' ') << node->name << "\n";
    for (Node* child : node->children) {
        printTree(child, depth + 1);   // 孩子再往下打印一层
    }
}

int main() {
    Node homework{"作业", {}};
    Node photos{"照片", {}};
    Node essay{"作文.docx", {}};
    Node math{"数学卷.pdf", {}};

    homework.children = {&essay, &math};   // 作业 文件夹里有两个文件

    Node root{"我的电脑", {}};
    root.children = {&homework, &photos};

    printTree(&root, 0);
    return 0;
}
tree = {
    "我的电脑": {
        "作业": {
            "作文.docx": {},
            "数学卷.pdf": {},
        },
        "照片": {},
    }
}

def print_tree(node, depth=0):
    for name, children in node.items():
        print(" " * (depth * 2) + name)
        print_tree(children, depth + 1)   # 孩子再往下打印一层

print_tree(tree)
▶ 运行结果
我的电脑
  作业
    作文.docx
    数学卷.pdf
  照片

这段输出本身就是树的形状：「我的电脑」是根，「作文.docx」「数学卷.pdf」「照片」 没有孩子，是叶子。代码里 print 函数自己调用自己，把每一层交给下一层去打印—— 这种写法叫递归，第 4 章还会再见到它。

小试牛刀：上面这棵文件夹树里，哪些是叶子节点？
🔑 第 6 小节小结

1. 树：一个根节点往下层层分叉，不能绕圈。

2. 术语：节点、父节点、子节点、叶子（没有孩子的节点）。

3. 适合分层数据：文件夹、家族谱、组织结构。

第 7 小节

图：任意相连的点

顶点与边 · 本章总结

树不允许绕圈，而现实中的很多关系偏偏会绕圈： 地铁的环线和换乘站、社交软件里互为好友的人群。 这时候需要用最后一种结构——图。

图的规矩最宽松：若干个点（顶点），点与点之间任意连线（边）。 没有根，没有层，想怎么连就怎么连。

存图的常用办法是邻接表：为每个点记一张「它和谁相连」的清单。 用我们学过的哈希表加数组就能实现——数据结构常常是这样互相搭起来的。 

#include <iostream>
#include <map>
#include <string>
#include <vector>
using namespace std;

int main() {
    // 邻接表：每个地铁站 → 与它直接相连的站
    map<string, vector<string>> metro;
    metro["公园"] = {"学校", "医院"};
    metro["学校"] = {"公园", "商场"};
    metro["医院"] = {"公园"};
    metro["商场"] = {"学校"};

    cout << "公园站的相邻站：";
    for (string station : metro["公园"]) {
        cout << station << " ";
    }
    return 0;
}
# 邻接表：每个地铁站 → 与它直接相连的站
metro = {
    "公园": ["学校", "医院"],
    "学校": ["公园", "商场"],
    "医院": ["公园"],
    "商场": ["学校"],
}

print("公园站的相邻站：", metro["公园"])
▶ 运行结果
公园站的相邻站：学校 医院
公园站的相邻站： ['学校', '医院']

「从公园怎么走到商场」「哪条换乘路线站数最少」—— 这些问题的答案就藏在这张邻接表里，而找出答案的方法，属于第 4 章的内容。

本章总结：什么时候用谁

栈

最近发生的先处理：撤销、后退。

队列

按到达顺序处理：任务排队、消息缓冲。

链表

经常在中间插入、删除。

哈希表 / 集合

按名字快速查找；只查在不在、要去重。

树

分层数据：文件夹、组织结构。

图

任意相连的网状关系：地铁、好友关系。
