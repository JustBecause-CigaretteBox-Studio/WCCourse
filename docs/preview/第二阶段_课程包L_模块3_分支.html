分支

平行宇宙，功能开发与主线的分离

开始模块 3 第 1 小节 → 模块 3 · 4 个小节 · 进度自动保存
第 1 小节

分支就是「平行宇宙」

想象一下：你的主线项目是一部连载漫画，而分支（Branch）就是同一部漫画的平行宇宙。在平行宇宙里，你可以大胆尝试新剧情，主宇宙的故事不受影响。

在 Git 里，默认的分支叫 main（或 master）。当你想开发新功能、修复 bug、或者做实验时，可以新建一个分支：

# 创建一个叫 feature-login 的新分支
git branch feature-login

# 切换到新分支
git checkout feature-login

# 或者一步到位（Git 2.23+ 推荐）
git switch -c feature-login

切换分支后，你的文件内容会立刻变成该分支的状态；切换回 main，一切又恢复原样。这就是「平行宇宙」的神奇之处。

第 2 小节

查看、创建与切换分支

分支操作是 Git 最常用、也最容易混淆的部分。核心命令只有几个：

# 查看所有分支，当前分支前有 * 号
git branch

# 创建新分支
git branch 新分支名

# 切换到已有分支
git checkout 分支名
# 或
git switch 分支名

# 创建并切换
git checkout -b 新分支名
# 或
git switch -c 新分支名

git branch 不会移动你的位置，它只是「挂牌子」；git checkout 或 git switch 才是真正「跳过去」。

小技巧：在新建分支前，先确保当前分支是干净的（没有未提交的修改），否则这些修改会跟着你一起「跳」过去，容易乱。

第 3 小节

分支的日常工作流

实际开发中，分支通常这样使用：

  • main / master：稳定版本，随时可以发布；
  • feature-xxx：新功能分支，开发完成后再合并回 main；
  • bugfix-xxx：紧急修复分支，修完合并。

典型流程如下：

# 1. 从稳定的主线开始
git switch main

# 2. 新建功能分支
git switch -c feature-emoji

# 3. 在分支上修改、提交
# （修改文件后）
git add .
git commit -m "添加表情功能"

# 4. 完成后再切换回 main 准备合并
git switch main

这样，main 始终保持干净，而新功能在独立分支里慢慢完善，互不影响。

第 4 小节

综合实战

为小游戏加一个「彩蛋分支」

假设你正在做一个叫 tiny-game 的小项目，现在想在不影响主线的情况下，加一个隐藏彩蛋。

任务：

  1. 在项目根目录执行 git switch -c easter-egg。
  2. 新建 easter.txt，写入一行彩蛋文字。
  3. add 并 commit。
  4. 用 git switch main 切回主线，确认 easter.txt 消失。
  5. 再切回 easter-egg，确认文件又回来了。
cd tiny-game
git switch -c easter-egg
echo "你发现了隐藏关卡！" > easter.txt
git add easter.txt
git commit -m "添加隐藏彩蛋"
git switch main
ls
# 此时 easter.txt 不在列表中
git switch easter-egg
ls
# 此时 easter.txt 又出现了

这个练习能让你真切感受到：分支让实验和主线完全隔离。
