第 1 小节

操作系统是电脑里的管家

如果你把电脑比作一栋大房子，那操作系统（Operating System，简称 OS）就是全天候待命的管家。它不负责打扫卫生，而是负责协调房子里的所有资源：厨房（CPU）、储物间（内存）、车库（硬盘）、门窗（输入输出设备）……让住在里面的程序们都能有条不紊地工作。

没有管家，程序们会为了抢资源打得头破血流；有了管家，它们就能排队、分时、共享。Windows、macOS、Linux、Android、iOS 都是常见的操作系统。

操作系统主要做三件大事：

  • 管理硬件：让 CPU、内存、硬盘、网卡等设备各司其职。
  • 运行程序：加载程序、分配资源、调度执行。
  • 提供接口：通过系统调用或命令行，让普通程序也能请求服务。

下面用一小段代码看一眼你当前的操作系统名字：

check_os.py
import platform

print("操作系统名称：", platform.system())
print("版本：", platform.release())
print("详细版本：", platform.version())
check_os.cpp
#include <iostream>

int main() {
#if defined(_WIN32)
    std::cout << "操作系统名称： Windows" << std::endl;
#elif defined(__APPLE__)
    std::cout << "操作系统名称： macOS" << std::endl;
#elif defined(__linux__)
    std::cout << "操作系统名称： Linux" << std::endl;
#else
    std::cout << "操作系统名称： Unknown" << std::endl;
#endif
    return 0;
}
第 2 小节

资源调度：CPU、内存、硬盘怎么分

电脑的资源是有限的，但想运行的程序有很多。操作系统就像一个经验丰富的管家， 回答三个问题：谁先用资源？用多久？用完了要不要给别人让座？

CPU 调度：CPU 一次只能执行少量指令。操作系统把 CPU 时间切成小片，轮流分给各个进程。因为切换非常快，我们感觉就像多个任务在“同时”运行。

内存分配：每个程序都需要内存来放代码和数据。操作系统负责分配、回收，并确保程序不会读到别人家的内存。

磁盘 I/O 调度：硬盘比 CPU 慢得多。操作系统会把读写请求排队、合并，尽量减少机械臂（或闪存控制器）的无效移动。

resource_sim.py
# 模拟一个简单的资源调度器
tasks = [("听音乐", 2), ("写代码", 5), ("下载文件", 3)]

# 按“耗时短优先”来调度
tasks.sort(key=lambda x: x[1])

print("调度顺序：")
for name, time in tasks:
    print(f"  {name}：分配 {time} 个时间片")
resource_sim.cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>

int main() {
    std::vector<std::pair<std::string, int>> tasks = {
        {"听音乐", 2},
        {"写代码", 5},
        {"下载文件", 3}
    };

    std::sort(tasks.begin(), tasks.end(),
        [](const std::pair<std::string, int> &a,
           const std::pair<std::string, int> &b) {
            return a.second < b.second;
        });

    std::cout << "调度顺序：" << std::endl;
    for (size_t i = 0; i < tasks.size(); ++i) {
        std::cout << "  " << tasks[i].first
                  << "：分配 " << tasks[i].second << " 个时间片" << std::endl;
    }
    return 0;
}
第 3 小节

内核与用户程序

操作系统内部也分“特权区”和“普通区”。内核（Kernel）是管家的核心团队，拥有最高权限，可以直接操作硬件；而普通程序（用户程序）只能待在外围，通过系统调用向内核提请求。

为什么这样设计？因为硬件太脆弱，不能谁都能乱碰。就像你不能随便进厨房改煤气管道，但你可以让专业的管道师傅帮你做。

常见的系统调用包括：创建进程、读写文件、申请内存、发送网络数据。Python 的很多标准库函数，底层都在替我们发起系统调用。

syscall_demo.py
import os

# getpid 是一个典型的系统调用：向内核询问当前进程 ID
print("当前进程 ID：", os.getpid())

# getcwd 也是系统调用：询问当前工作目录
print("当前工作目录：", os.getcwd())
syscall_demo.cpp
#include <iostream>
#ifdef _WIN32
#include <windows.h>
#include <direct.h>
#else
#include <unistd.h>
#endif

int main() {
#ifdef _WIN32
    std::cout << "当前进程 ID： " << GetCurrentProcessId() << std::endl;
    char cwd[1024];
    if (_getcwd(cwd, sizeof(cwd))) {
        std::cout << "当前工作目录： " << cwd << std::endl;
    }
#else
    std::cout << "当前进程 ID： " << getpid() << std::endl;
    char cwd[1024];
    if (getcwd(cwd, sizeof(cwd))) {
        std::cout << "当前工作目录： " << cwd << std::endl;
    }
#endif
    return 0;
}
第 4 小节

综合实战：写一个小小资源调度器

把本模块内容用起来

现在把前面的思路串起来。我们写一个极简的“任务调度器”：它接收几个任务，按优先级排序，然后假装给它们分配 CPU 时间片。这个小例子能帮你理解操作系统调度的核心——公平与效率的权衡。

tiny_scheduler.py
import time

tasks = [
    {"name": "浏览器", "priority": 3, "work": 4},
    {"name": "音乐",   "priority": 1, "work": 2},
    {"name": "游戏",   "priority": 5, "work": 6},
]

# 优先级高的先运行（数字越大越优先）
tasks.sort(key=lambda t: t["priority"], reverse=True)

for task in tasks:
    print(f"正在运行：{task['name']}（优先级 {task['priority']}）")
    for i in range(task["work"]):
        print(f"  执行第 {i+1}/{task['work']} 个时间片")
        time.sleep(0.2)
    print(f"{task['name']} 运行完毕，释放资源\n")
tiny_scheduler.cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <thread>
#include <chrono>

struct Task {
    std::string name;
    int priority;
    int work;
};

int main() {
    std::vector<Task> tasks = {
        {"浏览器", 3, 4},
        {"音乐",   1, 2},
        {"游戏",   5, 6}
    };

    std::sort(tasks.begin(), tasks.end(),
        [](const Task &a, const Task &b) {
            return a.priority > b.priority;
        });

    for (const auto &task : tasks) {
        std::cout << "正在运行：" << task.name
                  << "（优先级 " << task.priority << "）" << std::endl;
        for (int i = 0; i < task.work; ++i) {
            std::cout << "  执行第 " << (i + 1) << "/"
                      << task.work << " 个时间片" << std::endl;
            std::this_thread::sleep_for(std::chrono::milliseconds(200));
        }
        std::cout << task.name << " 运行完毕，释放资源\n" << std::endl;
    }
    return 0;
}

试着把 priority 改成一样，或者把 reverse=True 去掉，看看调度顺序有什么变化。真实的操作系统调度算法比这复杂得多，但基本思想是相通的。
