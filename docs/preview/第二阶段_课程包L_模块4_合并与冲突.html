第 1 小节

合并：让平行宇宙汇合

当你在分支上完成新功能后，需要把它合并（Merge）回主线。Git 提供了 git merge 命令来做这件事。

# 先切换到要接收改动的分支
git switch main

# 把 feature-login 的改动合并进来
git merge feature-login

合并后，main 分支上就会包含 feature-login 分支上的所有提交记录，两个分支的修改被整合到了一起。

如果 feature-login 是从 main 的最新提交分出来的，且 main 在此期间没有变化，Git 会执行快进合并（Fast-forward）：直接把 main 指针移动到 feature-login 的位置，非常干净。

第 2 小节

非快进合并与合并提交

如果 main 在 feature 分支开发期间也往前走了，Git 就无法简单快进。这时它会创建一个合并提交（Merge Commit），把两个分支的终点连接起来。

# 假设 main 和 feature 都各自有更新
git switch main
git merge feature-login

# 如果需要保留分支历史，可以加 --no-ff
git merge --no-ff feature-login

--no-ff 会强制产生一个合并提交，即使可以快进。这在团队协作中很常见，因为它能清晰保留「某个功能是在哪个分支上完成的」。

合并完成后，如果不需要原分支，可以删除它：

git branch -d feature-login
第 3 小节

冲突：当两个宇宙改了同一处

冲突（Conflict）是合并时最常见的问题。如果两个分支修改了同一文件的同一位置，Git 会停下来问：「这两处我该听谁的？」

发生冲突时，文件里会出现类似这样的标记：

<<<<<<< HEAD
欢迎回家
=======
欢迎光临
>>>>>>> feature-login

<<<<<<< HEAD 到 ======= 之间是当前分支的内容，======= 到 >>>>>>> 之间是另一个分支的内容。

解决冲突的方法就是：手动编辑文件，留下你想要的最终结果，删除所有 <<<、===、>>> 标记。然后重新 add 并 commit：

# 编辑文件，保留正确内容后
git add 冲突文件.txt
git commit -m "解决 feature-login 与 main 的冲突"
第 4 小节

综合实战

制造并解决一次冲突

光看不练假把式。这次我们故意制造一个冲突，然后把它解决掉。

任务：

  1. 在 main 上创建 story.txt，写一句「从前有座山」，提交。
  2. 创建分支 feature-a，把故事改成「从前有座高山」，提交。
  3. 切回 main，把故事改成「从前有座大山」，提交。
  4. 执行 git merge feature-a，会提示冲突。
  5. 打开 story.txt，决定保留「从前有座巍峨的高山」，删除冲突标记。
  6. add 并 commit 完成合并。
# main 上
echo "从前有座山" > story.txt
git add story.txt && git commit -m "主线：山的版本"

# feature-a 上
git switch -c feature-a
# 修改 story.txt 为 "从前有座高山"
git add story.txt && git commit -m "feature-a：高山"

# main 上再次修改
git switch main
# 修改 story.txt 为 "从前有座大山"
git add story.txt && git commit -m "主线：大山"

# 合并，触发冲突
git merge feature-a
# 手动编辑 story.txt 解决冲突后：
git add story.txt
git commit -m "解决冲突：统一为巍峨的高山"

完成后，用 git log --oneline --graph 看看分支合并的图形，会很有成就感。
