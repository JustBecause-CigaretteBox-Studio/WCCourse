第 1 小节

数全校人数需要多久

假设校长让你数全校有多少学生。方法一：逐个班级点名，把人数加起来。方法二：让每个班长直接报班级人数，你只把 30 个数字相加。

方法一相当于程序里的“循环遍历”，每个学生都要被数一次；方法二相当于“直接取关键值”，只用很少的步骤。如果学校有 1000 人，方法一大约要做 1000 次操作，方法二大约做 30 次操作，当然这也涉及到并行的问题，目前暂时忽略。

在算法里，我们用时间复杂度来描述这种“操作次数随数据量增长的变化趋势”。它不精确到毫秒，而是回答一个问题：如果数据变成原来的 10 倍，程序会变慢多少倍？

这就好比搬家：东西少的时候差别不大，东西一多，不同搬法的差距就会非常刺眼。

第 2 小节

大 O 记号：给复杂度起个名字

为了比较算法快慢，计算机科学家发明了大 O 记号。它只保留增长最快的那一项，忽略常数和低次项。比如 3n+5 和 100n+20，在大 O 看来都是 O(n)，因为数据量足够大时，前面的系数影响越来越小。

对新手来说，记住这三种最常见的复杂度就够了：

大 O名字含义例子
O(1)常数时间不管数据多少，步骤固定取数组第一个元素
O(n)线性时间数据翻倍，操作也翻倍从头到尾遍历列表
O(n²)平方时间数据翻倍，操作变成 4 倍两层嵌套循环

打个比方：O(1) 像从冰箱里拿一瓶饮料；O(n) 像把冰箱里的饮料一瓶瓶数完；O(n²) 像把饮料两两搭配做品尝测试，搭配组合会暴增。

再复习一遍：饮料两两搭配，严格来讲方法数量是 n(n-1)/2，

第 3 小节

数一下循环次数

判断复杂度，最实用的办法就是看代码里的循环。没有循环、只固定执行几步的操作，通常是 O(1)。一个遍历 n 个元素的循环，通常是 O(n)。两个嵌套循环，每个都跑 n 次，通常是 O(n²)。

不同复杂度的循环
def find_first(items):
    return items[0]          # O(1)：只取第一个，和列表多长无关

def count_all(items):
    total = 0
    for x in items:          # O(n)：每个元素访问一次
        total += x
    return total

def count_pairs(items):
    count = 0
    for i in range(len(items)):
        for j in range(len(items)):  # O(n²)：每个元素都和其他元素配对
            if i != j:
                count += 1
    return count
count_loops.cpp
#include <iostream>
#include <vector>
using namespace std;

int find_first(vector<int>& items) {
    return items[0];          // O(1)：只取第一个，和列表多长无关
}

int count_all(vector<int>& items) {
    int total = 0;
    for (int x : items) {     // O(n)：每个元素访问一次
        total += x;
    }
    return total;
}

int count_pairs(vector<int>& items) {
    int count = 0;
    int n = items.size();
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {  // O(n²)：每个元素都和其他元素配对
            if (i != j) {
                count += 1;
            }
        }
    }
    return count;
}

int main() {
    vector<int> items = {1, 2, 3, 4, 5};
    cout << find_first(items) << endl;
    cout << count_all(items) << endl;
    cout << count_pairs(items) << endl;
    return 0;
}

注意，大 O 说的是最坏情况或一般情况。比如查找元素，如果运气好第一个就命中，那实际很快；但复杂度假设的是“可能要查到最后”，这样比较才有意义。

第 4 小节

综合实战：比比两种求和法

用计时器感受复杂度的差异

还记得模块 1 里的 1 到 n 求和吗？循环法的时间复杂度是 O(n)，公式法（n*(n+1)/2）的时间复杂度是 O(1)。数据小的时候感觉不到差别，数据大到百万、千万时，差距就出来了。

下面这个小程序用一个简单的计时方法，比较两种方法在 n=1000000 时的表现。注意运行时间受电脑状态影响，不一定每次相同，但趋势是稳定的。

计时比较
import time

def sum_loop(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

def sum_formula(n):
    return n * (n + 1) // 2

n = 1000000

start = time.time()
print(sum_loop(n))
print("循环法耗时：", time.time() - start, "秒")

start = time.time()
print(sum_formula(n))
print("公式法耗时：", time.time() - start, "秒")
compare_sum.cpp
#include <iostream>
#include <chrono>
using namespace std;

long long sum_loop(long long n) {
    long long total = 0;
    for (long long i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

long long sum_formula(long long n) {
    return n * (n + 1) / 2;
}

int main() {
    long long n = 1000000;

    auto start = chrono::high_resolution_clock::now();
    cout << sum_loop(n) << endl;
    auto end = chrono::high_resolution_clock::now();
    chrono::duration<double> elapsed = end - start;
    cout << "循环法耗时：" << elapsed.count() << " 秒" << endl;

    start = chrono::high_resolution_clock::now();
    cout << sum_formula(n) << endl;
    end = chrono::high_resolution_clock::now();
    elapsed = end - start;
    cout << "公式法耗时：" << elapsed.count() << " 秒" << endl;

    return 0;
}

动手把 n 改成更大的数，看看循环法会不会明显变慢，公式法是否几乎不变。这种“把 n 调大、观察时间如何增长”的思维方式，就是分析时间复杂度的起点。
