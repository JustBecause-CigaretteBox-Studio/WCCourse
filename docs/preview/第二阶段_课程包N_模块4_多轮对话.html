第 1 小节

为什么一次 prompt 不够

好代码是改出来的

很多新手期待一次 prompt 就拿到完美代码，然后复制粘贴收工。 但现实中，第一次输出通常只能达到 60 分： 功能大方向对，但细节、风格、边界处理都可能不到位。

这就像做饭：第一遍炒出来的菜能吃，但咸淡、火候、配料比例还要调整。 AI 就是你的厨师，你需要尝一口，再告诉它「再淡一点」「多加点蒜」。

多轮迭代示例
第 1 轮：
"帮我做一个待办事项网页。"
→ AI 给出一个基础版，能添加任务。

第 2 轮：
"很好，现在加上删除按钮，并且让已完成任务有删除线。"
→ AI 补充删除和样式。

第 3 轮：
"数据现在刷新就丢了，请用 localStorage 保存任务。"
→ AI 加入持久化。

第 4 轮：
"界面在手机上有点挤，请优化移动端布局。"
→ AI 调整响应式样式。

每一轮都基于上一轮的成果继续优化。你的任务不是一次性想全， 而是每次只推进一个明确的改进点。

第 2 小节

给 AI 有效反馈

具体、可验证、带上下文

想让 AI 越改越好，你的反馈质量是关键。 模糊的反馈会让 AI 猜你的意思，结果越改越偏。

反馈对比
❌ 模糊反馈：
"这个页面不好看，改一下。"
→ AI 不知道你要什么风格，可能改成另一种丑法。

✅ 具体反馈：
"标题字体太大，在手机上占了两行。请把标题字号从 32px 改成 24px，
并给卡片加 16px 的内边距，让内容不贴边。"

有效反馈的三要素：

有效反馈公式
1. 具体位置
   "在 login 函数里……"
   "页面顶部的导航栏……"

2. 具体问题
   "点击提交按钮没有反应。"
   "输入为空时还能提交，应该阻止。"

3. 期望结果
   "我希望提交后显示'登录成功'并跳转到首页。"
   "希望输入为空时，输入框边框变红并提示'请输入内容'。"

另外，每次只改一件事。如果你一次性说 8 个问题， AI 可能漏掉一半。把它拆成 8 轮，每轮专注一个点，成功率更高。

反馈 prompt 模板
请修改上一版的代码，具体要求如下：

位置：_____
问题：_____
期望结果：_____

注意事项：
- 不要改动其他无关部分
- 如果我的需求有歧义，请先问我确认
第 3 小节

分而治之：先架构，后细节

控制迭代的节奏

多轮对话最怕「胡子眉毛一把抓」：一边改数据结构，一边改样式，一边加功能。 结果常常是改了这里、坏了那里。

更好的策略是分而治之：

迭代阶段建议
阶段 1：搭骨架
- 确认有哪些页面/组件
- 确认数据结构和文件组织
- 不追求美观，先跑通主流程

阶段 2：补功能
- 逐个实现核心功能
- 每实现一个就运行验证

阶段 3：修细节
- 改样式、提示文案、动画
- 处理边界和异常

阶段 4：做验收
- 对照最初的需求清单逐条检查
- 让 AI 自己生成测试用例并跑一遍

每一轮开始前，先告诉 AI 当前处于哪个阶段：

阶段声明示例
我们现在处于阶段 2：补功能。
请先不要改样式，只实现以下功能：
1. 任务可以标记为完成
2. 已完成的任务可以取消完成
3. 列表底部显示"共 X 项，已完成 Y 项"

这样 AI 会聚焦于当前目标，不容易「顺手」改一堆别的东西。 如果发现它跑偏了，立刻把它拉回来：「请不要改其他部分，只改我说的这一点。」

第 4 小节

综合实战：三轮迭代优化一个计数器

体验多轮对话的力量

现在用一个小例子练习多轮迭代。你将用三轮对话，把一个最简陋的计数器改造成一个可用的工具。

初始版本：

第 0 版：最简单计数器
<button onclick="count++">+1</button>
<span id="num">0</span>

<script>
let count = 0;
const num = document.getElementById("num");
</script>

这个版本有问题：点击按钮后数字不会更新，因为它没有重新渲染。

你的三轮迭代任务：

迭代计划
第 1 轮：修复基础 bug
prompt：
"当前代码点击 +1 后数字没有更新。请修复这个问题，
并给 button 增加 -1 和重置按钮。"

第 2 轮：增加约束和样式
prompt：
"请给计数器增加最小值 0 和最大值 100 的限制，
并用 CSS 让三个按钮排成一排，按钮之间留 8px 间距。"

第 3 轮：持久化
prompt：
"请把当前数值保存到 localStorage，刷新页面后数字不丢失。
但要保证首次打开时显示 0。"

记录你的迭代日志：

迭代日志模板
第 1 轮反馈：
- AI 是否理解了问题？_____
- 有没有引入新问题？_____

第 2 轮反馈：
- 边界处理是否符合预期？_____
- 样式是否适配手机？_____

第 3 轮反馈：
- 刷新后数值是否正确？_____
- 清除浏览器数据后是否从 0 开始？_____

这个练习虽小，但它完整模拟了真实开发：发现 bug → 提需求 → 验收 → 再优化。
