第 1 小节

一对一关系

一对一关系表示：A 表中的一条记录，最多对应 B 表中的一条记录。例如，一个用户只有一个实名认证信息。

用户与认证信息
CREATE TABLE users (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
);

CREATE TABLE profiles (
    user_id INTEGER PRIMARY KEY,  -- 既做主键，也关联 users.id
    phone   TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

这里 profiles.user_id 既是主键，也是外键，保证了一个用户只能有一条认证信息。

第 2 小节

一对多关系

一对多是最常见的关系。例如，一个班级有多名学生，一位作者写了多本书。

班级与学生
CREATE TABLE classes (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
);

CREATE TABLE students (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    name     TEXT NOT NULL,
    class_id INTEGER,
    FOREIGN KEY (class_id) REFERENCES classes(id)
);

在「多」的那一方（学生表）加上外键，指向「一」的那一方（班级表）。这样就能知道每个学生属于哪个班级。

第 3 小节

外键约束

外键（Foreign Key）不仅是字段之间的关联，更是一种约束：它禁止插入不存在的引用。

比如，如果班级表里没有 id=99 的班级，那么向学生表插入 class_id=99 的记录就会被数据库拒绝。

启用外键约束
import sqlite3

conn = sqlite3.connect("school.db")
cursor = conn.cursor()

# SQLite 默认不强制外键，需要手动开启
cursor.execute("PRAGMA foreign_keys = ON")

# 现在如果 classes 表没有对应 id，插入 students 就会报错
cursor.execute("INSERT INTO students (name, class_id) VALUES ('小王', 99)")
conn.commit()

启用 PRAGMA foreign_keys = ON 后，SQLite 才会真正检查外键，防止出现「悬空」记录。

第 4 小节

综合实战：设计一个小图书馆

作者与书的一对多关系

来设计一个小图书馆数据库。需求是：记录作者和书，一个作者可以有多本书。

图书馆表结构
CREATE TABLE authors (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
);

CREATE TABLE books (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    title    TEXT NOT NULL,
    author_id INTEGER NOT NULL,
    FOREIGN KEY (author_id) REFERENCES authors(id)
);

动手任务：插入几位作者，再为每位作者插入几本书；然后写一条 SQL，查询「某作者的所有书名」。
