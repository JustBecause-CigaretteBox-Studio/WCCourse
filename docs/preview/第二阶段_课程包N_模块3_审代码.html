第 1 小节

AI 也会犯错

别把 AI 输出当圣旨

AI 写代码很快，但它不是全知全能。它可能犯三类典型错误：

1. 幻觉（Hallucination）

AI 可能编造一个不存在的函数、库或 API。比如你让它用 Python 处理日期， 它可能给你写一个 datetime.smart_parse()，这个函数根本不存在。

幻觉示例 (Python)
from datetime import datetime

# ❌ 错误：datetime 没有 smart_parse 方法
t = datetime.smart_parse("2024-08-20")
print(t)

# ✅ 正确做法
from datetime import datetime
t = datetime.strptime("2024-08-20", "%Y-%m-%d")
print(t)
同一思路 (C++)
#include <iostream>
#include <sstream>
#include <iomanip>
#include <ctime>

int main() {
    // ❌ 错误：C++ 标准库没有 smart_parse
    // std::tm t = smart_parse("2024-08-20");

    // ✅ 正确做法：用 stringstream + get_time
    std::tm t{};
    std::istringstream ss("2024-08-20");
    ss >> std::get_time(&t, "%Y-%m-%d");
    if (ss.fail()) {
        std::cerr << "解析失败\n";
    } else {
        std::cout << "解析成功\n";
    }
    return 0;
}

2. 过时代码

AI 训练数据有截止日期，它可能推荐已经被弃用的写法。 比如某些旧的 jQuery 写法、Python 2 的语法，或者几年前的前端工具链。

3. 忽略边界情况

AI 常常写出「正常情况能用」的代码，但遇到空输入、特殊字符、网络失败时就崩了。

边界示例
// AI 可能生成
function divide(a, b) {
  return a / b;
}

// 更安全的版本
function divide(a, b) {
  if (b === 0) return "不能除以零";
  if (typeof a !== "number" || typeof b !== "number") return "请输入数字";
  return a / b;
}

审代码的第一步，就是建立「怀疑精神」：AI 给的不是最终答案，而是草稿。

第 2 小节

静态检查：读代码找 bug

不运行也能发现的问题

静态检查就是盯着代码看，不运行它。重点看五个地方：

静态检查清单
1. 变量名和函数名是否一致？
   - 声明时用 userName，后面写成 username 就会报错。

2. API 是否存在？
   - 用不认识的函数/方法时，去官方文档确认一下。

3. 逻辑是否自洽？
   - if 条件是否覆盖了所有分支？
   - 有没有死循环的可能？

4. 类型是否匹配？
   - 字符串和数字直接相加，结果可能出乎意料。

5. 安全问题：
   - 用户输入有没有被直接拼进 SQL/HTML？
   - 敏感信息有没有写死在代码里？

你还可以把代码直接丢给 AI，让它扮演「代码审查员」：

审查 prompt 示例
请扮演一名资深代码审查员，检查下面这段代码。
请从以下角度分析：
1. 是否有明显 bug 或边界情况没处理
2. 是否有性能或安全问题
3. 变量命名和可读性如何
4. 给出修改建议，并解释原因

第 3 小节

动态检查：跑起来验证

运行 + 边界测试

代码能跑通，不等于代码没问题。动态检查的核心是： 用真实输入，尤其是边界输入，去测试它。

比如 AI 给你写了一个「判断是否为成年人」的函数：

待测试函数
function isAdult(age) {
  return age >= 18;
}

你应该测试：

边界测试用例
正常值：
- isAdult(20) → true
- isAdult(17) → false

边界值：
- isAdult(18) → true（临界）
- isAdult(0)  → false（最小值）

异常值：
- isAdult(-1)    → 应该返回 false 还是报错？
- isAdult("abc") → 应该返回什么？
- isAdult(null)  → 会报错吗？

动态检查的另一个好办法是：让 AI 自己写测试用例。 你只需要补充一句约束：「请为这段代码编写单元测试，覆盖正常和边界情况」。

让 AI 写测试的 prompt
请为下面的 isAdult 函数编写测试用例，
要求覆盖：正常值、边界值、异常输入。
输出格式：输入 → 期望输出 → 实际输出（如果有）

function isAdult(age) {
  return age >= 18;
}

记住：没运行过的代码不要相信，没测过边界的代码不要上线。

第 4 小节

综合实战：审查一段 AI 生成的登录代码

找出 bug 并给出反馈

现在实战练习审查能力。下面是一段 AI 生成的「用户登录」代码，请你找出至少 3 个问题。

待审查代码
function login(email, password) {
  if (email == "admin@test.com" && password == "123456") {
    return { success: true, token: "admin-token-123" };
  }
  return { success: false };
}

请你从以下角度审查：

审查角度
1. 安全问题：这段代码有哪些明显安全隐患？
2. 边界情况：如果 email 或 password 为空会怎样？
3. 可维护性： hardcode 用户密码有什么问题？
4. 功能完整性：登录成功或失败，前端应该怎么处理？

参考答案（先自己找完再看）：

参考答案
1. 密码明文比较且直接出现在代码中，任何人打开源码都能看到。
2. 没有输入校验，空字符串也能触发比较。
3. token 是固定的字符串，无法区分不同用户和会话。
4. 没有错误提示信息，前端不知道具体失败原因。
5. 使用 == 而非 ===，可能发生类型转换导致意外通过。

找完 bug 后，练习把问题整理成给 AI 的反馈：

反馈 prompt 模板
请修改下面的 login 函数，解决以下问题：
1. 不要 hardcode 用户密码
2. 校验 email 和 password 不能为空
3. token 应该随机生成或从外部传入
4. 返回清晰的错误信息
5. 使用严格相等 ===
