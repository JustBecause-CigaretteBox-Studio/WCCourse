第 1 小节

把大象放进冰箱

老笑话：把大象放进冰箱需要三步——打开冰箱、放进大象、关上冰箱。这其实就是 WBS 的精髓：把一件看起来不可能完成的大事，拆成若干件可以执行的小事。

（作者至今没明白笑点是什么）

WBS 全称 Work Breakdown Structure，意思是「工作分解结构」。它告诉我们：不要盯着整头大象，要盯着下一步动作。

把大象放进冰箱
目标：把大象放进冰箱
├─ 打开冰箱门
├─ 把大象装进去
│   ├─ 确认大象大小
│   └─ 微调大象位置
└─ 关上冰箱门

编程项目也一样。不要一上来就写「整个 APP」，而是把它拆成模块、再拆成功能、再拆成一行行代码。

第 2 小节

拆到多细才够？

拆解的粒度有一个简单标准：拆到「一个人能在几小时内完成」为止。太粗还是一头大象，太细则会变成无限清单。

常用的两个原则是 MECE：Mutually Exclusive（彼此不重叠）、Collectively Exhaustive（合起来不遗漏）。

拆分对比
不好的拆分：
1. 写代码
2. 做界面
3. 测试一下

好的拆分（口算题生成器）：
1. 随机生成两个加数
2. 组合成题目并显示
3. 接收用户输入的答案
4. 判断对错并计分
5. 输出最终结果

右边每一项都直接对应一段代码，不会让人无从下手。

给口算题生成器做 WBS

现在用 WBS 把「口算题生成器 2.0」的需求清单拆成可执行的小任务。

WBS 任务分解
口算题生成器 2.0
├─ 题目生成
│   ├─ 根据年级确定数字范围
│   ├─ 随机生成运算符（+ 或 -）
│   └─ 生成指定数量的题目
├─ 用户答题
│   ├─ 显示题目与输入框
│   └─ 记录用户答案
├─ 判分与反馈
│   ├─ 对比正确答案
│   ├─ 计算得分
│   └─ 显示结果
└─ 重新开始
    └─ 清空状态并生成新题

看到这张图，你就知道先做哪一步、后做哪一步，每一步完成后也能明确验收。
