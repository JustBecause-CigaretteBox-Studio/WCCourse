仓库、提交、历史记录、回退

第 1 小节

创建仓库：git init

仓库（Repository）是 Git 保存项目历史的地方。创建仓库也叫「初始化」，命令非常简单：

# 1. 先创建一个项目文件夹并进入
mkdir my-project
cd my-project

# 2. 把这里变成 Git 仓库
git init

执行后，Git 会在当前目录下生成一个隐藏的 .git 文件夹。这里存放着所有的版本历史，不要手动删除或修改它。

一个文件夹被 git init 之后，Git 就会开始「盯梢」这个目录里的文件变化。但注意：它不会自动保存所有变化，还需要你手动决定哪些变化要进入历史。

第 2 小节

提交快照：git add 与 git commit

Git 的核心工作流程就两步：先把改动放进暂存区，再把暂存区的内容提交到仓库。

# 创建一个文件
echo "Hello Git" > readme.txt

# 把它加入暂存区
git add readme.txt

# 提交到仓库，并写一句说明
git commit -m "创建 readme.txt，写入初始问候语"

git add 相当于「把作业放到讲台上」，git commit 相当于「老师把作业收进档案袋」。如果只改文件不 add，Git 不会把这次改动归档。

如果你想一次性提交所有修改过的文件，可以用：

git add .
git commit -m "修改了若干文件"

不过新手建议先逐个文件 git add，这样能更清楚自己到底提交了什么。

第 3 小节

查看状态与历史

提交完并不意味着结束。日常最常用的是这两个「检查」命令：

# 查看当前有哪些改动、哪些文件在暂存区
git status

# 查看提交历史
git log

# 查看简洁版历史（一行一个提交）
git log --oneline

git status 会高亮显示三种状态：已修改（modified）、已暂存（staged）、未跟踪（untracked）。只要看不懂当前文件夹发生了什么，就先运行它。

如果你发现最新一次提交写错了，或者想暂时回到某个旧版本看看，可以用：

# 查看某个旧版本的内容（只读）
git checkout 提交ID

# 彻底回退到上一个版本（慎用，会丢失最新改动）
git reset --hard HEAD~1

其中 HEAD 代表当前所在版本，HEAD~1 代表上一个版本。用 git log --oneline 看到的短 ID 就是「提交ID」。

第 4 小节

综合实战

给一首小诗做版本管理

本实战的目标是用 Git 管理一首三行小诗的创作过程。

任务：

  1. 新建文件夹 poem 并进入，执行 git init。
  2. 创建 poem.txt，写入第一版诗句，add 并 commit。
  3. 修改第二句诗，再次 add 并 commit。
  4. 修改第三句诗，再次 add 并 commit。
  5. 用 git log --oneline 查看三个提交，然后用 git checkout 翻看第二版。
mkdir poem && cd poem
git init
echo "春眠不觉晓" > poem.txt
git add poem.txt && git commit -m "第一句"
# 手动修改 poem.txt 第二句，然后：
git add poem.txt && git commit -m "第二句"
# 再修改第三句，然后：
git add poem.txt && git commit -m "第三句"
git log --oneline

完成后，你就拥有了一条真正的时间线：每一句修改都被 Git 保存下来了。
