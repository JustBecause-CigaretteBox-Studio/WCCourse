链表

会生长的数组，插入删除不再搬家

第 1 小节

链表是什么

像火车车厢一样连在一起的数据

我们已经学过数组：把所有元素按顺序排成一排，就像电影院里固定位置的座位。数组查某个位置很快，但想在中间插入或删除一个元素，后面的所有元素都要「搬家」。

链表则像一列火车：每节车厢只知道自己前面/后面连着哪一节。只要找到某一节，把它的「前面/后面是谁」改一下，就能完成插入或删除，不需要移动其他车厢。我们来深入研究这种数据结构。

链表的每个元素叫作节点（Node），节点里存两样东西：数据本身，以及指向下一个节点的「钩子」（指针或引用）。

class Node:
    def __init__(self, value):
        self.value = value  # 当前车厢装的数据
        self.next = None    # 下一节车厢，目前为空
struct Node {
    int value;      // 当前车厢装的数据
    Node* next;     // 指向下一节车厢的指针
    Node(int v) : value(v), next(nullptr) {}
};
第 2 小节

插入与删除

只需改两根线，不用搬全家

在链表中间插入一个新节点，只需要做两件事：让前一个节点指向新节点，再让新节点指向原来的后一个节点。删除也是一样：让前一个节点直接指向被删节点的下一个节点。

因为其他节点在内存里不需要连续排列，插入和删除的平均时间复杂度是 O(1)（前提是已经找到了位置）。对比数组中间插入的 O(n)，链表更适合频繁增删的场景。

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, value):       # 在链表头部插入
        new_node = Node(value)
        new_node.next = self.head
        self.head = new_node

    def remove_first(self):            # 删除头部节点
        if self.head:
            self.head = self.head.next
void push_front(Node*& head, int value) {
    Node* newNode = new Node(value);
    newNode->next = head;
    head = newNode;
}

void remove_first(Node*& head) {
    if (head) {
        Node* temp = head;
        head = head->next;
        delete temp;            // C++ 里记得释放内存
    }
}
第 3 小节

遍历链表

从头开始一节一节往后走

链表不像数组那样能直接跳到第 5 个位置。想知道第 5 个节点的值，只能从头节点出发，沿着 next 一步一步走，直到数到第 5 个。因此链表的按索引查找是 O(n)。

遍历的核心思想很简单：拿一个临时变量 cur 指向当前节点，反复执行「处理当前节点 → 走到下一个节点」，直到 cur 变成空。

def print_list(head):
    cur = head
    while cur:
        print(cur.value, end=" -> ")
        cur = cur.next
    print("None")

# 使用示例
lst = LinkedList()
for x in [3, 7, 5]:
    lst.push_front(x)
print_list(lst.head)   # 输出 5 -> 7 -> 3 -> None
void printList(Node* head) {
    Node* cur = head;
    while (cur) {
        cout << cur->value << " -> ";
        cur = cur->next;
    }
    cout << "None\n";
}

// 使用示例
Node* head = nullptr;
push_front(head, 3);
push_front(head, 7);
push_front(head, 5);
printList(head);   // 输出 5 -> 7 -> 3 -> None
第 4 小节

综合实战：反转链表

把火车车厢的顺序倒过来

反转链表是面试和算法题里的经典操作。思路是：从头到尾遍历链表，每遇到一个节点，就把它从原来的方向上「掰」过来，指向前面那个节点。

具体需要三个指针：prev（前一个节点）、cur（当前节点）、nxt（临时保存当前节点的下一个节点）。一遍遍历就能完成反转。

def reverse(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next      # 先记住下一个
        cur.next = prev     # 当前节点掉头指向前一个
        prev = cur          # 前一个前进一步
        cur = nxt           # 当前也前进一步
    return prev

# 使用
lst.head = reverse(lst.head)
print_list(lst.head)   # 输出 3 -> 7 -> 5 -> None
Node* reverse(Node* head) {
    Node* prev = nullptr;
    Node* cur = head;
    while (cur) {
        Node* nxt = cur->next;
        cur->next = prev;
        prev = cur;
        cur = nxt;
    }
    return prev;
}

// 使用
head = reverse(head);
printList(head);   // 输出 3 -> 7 -> 5 -> None

练习：在上面的代码基础上，尝试写一个在链表末尾追加节点 push_back 的函数，然后用它重新创建一条 3 -> 7 -> 5 的链表，再反转一次。

第 5 小节

双向链表

每个节点再多一根往回走的线

单向链表有个不方便：只能从前往后走。如果已经站在中间某个节点，想回到上一个节点，只能从头再遍历一遍。双向链表（Doubly Linked List）给每个节点额外加了一根 prev 指针，指向前一个节点，于是火车就能双向行驶了。

图：双向链表节点比单向多了一个 prev 指针

整条链子于是同时有两条方向相反的“轨道”：实线 next 往后走，虚线 prev 往前走。

图：双向链表的两条轨道（next 往后，prev 往前）

代价与好处。 插入或删除一个节点时，除了改两根 next 线，还要同步改两根 prev 线，相当于“改四根线”，操作更繁琐、也多占一点内存。但换来两个实打实的好处：可以双向遍历，以及——当你已经拿着某个节点的引用时——删除它只要 O(1)（单向链表删除已知节点还得先找到它的前驱，是 O(n)）。

class DNode:
    def __init__(self, value):
        self.value = value
        self.prev = None   # 新增：指向前一个节点
        self.next = None   # 指向下一个节点

class DoublyList:
    def __init__(self):
        self.head = None

    def push_front(self, value):
        node = DNode(value)
        node.next = self.head
        if self.head:
            self.head.prev = node   # 别忘了把老 head 的 prev 指回来
        self.head = node
struct DNode {
    int value;
    DNode* prev;   // 新增：指向前一个节点
    DNode* next;   // 指向下一个节点
    DNode(int v) : value(v), prev(nullptr), next(nullptr) {}
};

void push_front(DNode*& head, int value) {
    DNode* node = new DNode(value);
    node->next = head;
    if (head) {
        head->prev = node;   // 别忘了把老 head 的 prev 指回来
    }
    head = node;
}
第 6 小节

哨兵节点

用一个假节点，消灭所有“边界特判”

前面写插入/删除时，你可能想到过一堆让人头大的特殊判断，例如：要删的是头节点怎么办？这些“边界情况”最容易写错，也最不优雅。

哨兵节点（Sentinel）就是专门解决这个问题的：在链表真正的数据之前，放一个永远存在、但不存任何真实数据的“假节点”（也叫哑节点 dummy head）。它像一个固定的哨兵，站在队伍最前面。

图：哨兵（紫色）永远站在最前面，真实节点从它后面开始

有了哨兵，原先的“特殊情况”全消失了：

  • 链表为空不再需要判断——哨兵永远在，队伍永远“至少有一个节点”（尽管它不是真数据）。
  • 在头部插入 退化为“在哨兵后面插入”，和“在中间插入”用的是同一套代码，没有 if (head == nullptr) 分支。
  • 删除头节点 也变成“删除哨兵后面的节点”，统一处理。

下面用哨兵重写了插入和删除，注意代码里完全没有了空判断：

class SentinelList:
    def __init__(self):
        self.head = DNode(None)   # 哨兵：数据填 None，永远存在

    def push_front(self, value):
        node = DNode(value)
        node.next = self.head.next
        if self.head.next:        # 只有在“后面真有节点”时才把它的 prev 指回
            self.head.next.prev = node
        node.prev = self.head
        self.head.next = node     # 永远插在哨兵后面

    def remove_first(self):
        real = self.head.next
        if not real: return        # 真没数据了才提前返回
        self.head.next = real.next
        if real.next:
            real.next.prev = self.head
struct SentinelList {
    DNode* head;            // 哨兵，永远非空
    SentinelList() { head = new DNode(0); }   // 数据随便填，不真正使用
};

void push_front(SentinelList& list, int value) {
    DNode* node = new DNode(value);
    node->next = list.head->next;
    if (list.head->next) list.head->next->prev = node;
    node->prev = list.head;
    list.head->next = node;        // 永远插在哨兵后面
}

void remove_first(SentinelList& list) {
    DNode* real = list.head->next;
    if (!real) return;             // 真没数据了才提前返回
    list.head->next = real->next;
    if (real->next) real->next->prev = list.head;
    delete real;
}

哨兵的代价是多用了一个节点、且遍历时要跳过它（从 head.next 开始才是真数据）。但在频繁增删、尤其是写库/框架时，它换来的代码简洁和少 bug 往往非常划算。双向链表 + 哨兵，是很多工业级链表（比如 Linux 内核链表、Java LinkedHashMap）的标准搭配。
