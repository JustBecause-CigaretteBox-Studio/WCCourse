怎么给 AI 写「剧本」

需求描述的艺术：角色、目标、约束

开始模块 2 第 1 小节 → 模块 2 · 4 个小节 · 进度自动保存
第 1 小节

角色：让 AI 扮演谁

一个明确的身份能立刻提升回答质量

给 AI 一个角色，就像给演员一份人物小传。它知道该用什么语气、关注什么、忽略什么。

比较下面两个 prompt：

无角色 vs 有角色
❌ 无角色：
"帮我写个登录页面。"

✅ 有角色：
"你是一名有 5 年经验的前端工程师，熟悉无障碍访问（a11y）和移动端适配。
请帮我写一个简洁的登录页面，要求：
- 邮箱和密码输入框都有正确的 label
- 密码框支持显示/隐藏切换
- 在 375px 宽的手机上也能正常显示"

角色不仅决定代码风格，也决定 AI 会不会主动提醒你一些细节。 比如「安全工程师」角色会提醒你密码不要明文存储； 「初级讲师」角色会用更通俗的语言解释代码。

常用角色参考：

角色清单
- 前端工程师（React / Vue / 原生 HTML+CSS+JS）
- 后端工程师（Python Flask / Node.js / Go）
- 全栈工程师
- 技术面试官
- 代码审查员
- 对编程一窍不通的产品经理
- 给小学生讲课的老师

选择角色的原则是：你希望 AI 用谁的眼光来审视这个任务。

第 2 小节

目标：说清楚"做什么"

描述结果，而不是过程

很多新手容易一上来就告诉 AI 「怎么写」，比如：「用 for 循环遍历数组」。 但更好的方式是说清楚你想要什么结果，让 AI 自己选实现路径。

过程 vs 结果
❌ 关注过程：
"写一个 for 循环，把数组里的数字相加。"

✅ 关注结果：
"给定一个数字数组，返回所有元素的和。
如果数组为空，返回 0。
请用 JavaScript 实现，并给出单元测试。"

描述目标时，可以套用「谁 + 做什么 + 达到什么效果」的句式：

目标公式
作为 [用户角色]，
我希望 [执行某个动作]，
从而 [获得某种结果 / 解决某个问题]。

例如：

目标示例
作为一名网站访客，
我希望在提交表单后看到清晰的错误提示，
从而知道哪个字段填错了、应该怎么改。

目标写得越具体，AI 越不容易跑偏。如果只说「做一个好看的页面」， AI 可能给你一堆动画；你要的是「简洁、加载快、信息层级清晰」。

第 3 小节

约束：给 AI 画边界

技术栈、边界、风格、安全

没有约束的 AI 就像一个没有预算的导演，会尽情地加特效。 约束让你的 prompt 从「随意发挥」变成「按规矩办事」。

常见的约束维度：

约束清单
1. 技术栈约束
   - "只用原生 HTML + CSS + JS，不引入框架"
   - "后端用 Python Flask，数据库用 SQLite"

2. 范围约束
   - "只实现 MVP，不要用户系统、不要后台管理"
   - "本次只改样式，不动逻辑"

3. 风格约束
   - "代码要简洁，注释用中文"
   - "UI 参考 Material Design，圆角大、阴影轻"

4. 安全约束
   - "不要在前端暴露 API Key"
   - "所有用户输入都要做转义，防止 XSS"

5. 输出约束
   - "只输出代码，不要解释"
   - "先给出整体思路，再输出代码"

约束不是越多越好。一次给太多约束，AI 可能记不住或互相冲突。 建议先给最重要的 3-5 条，后续再补充。

一个好的完整 prompt，通常是「角色 + 目标 + 约束」的组合：

完整 prompt 示例
角色：你是一名熟悉原生 JS 的前端工程师。

目标：帮我做一个待办事项网页，用户可以添加、完成、删除任务，
      已完成任务出现在列表下方，数据存在浏览器本地。

约束：
- 单文件 HTML，不需要后端
- 界面要简洁，适配手机
- 用 localStorage 保存数据
- 代码注释用中文，变量名用英文
- 先输出实现思路，再输出完整代码
第 4 小节

综合实战：写一份待办事项应用的完整 prompt

把角色、目标、约束组合起来

现在把前三小节的内容组合成一份「剧本」，让 AI 按你的要求生成一个待办事项应用。

任务：

在下面的模板基础上，补充你自己的细节，然后把完整 prompt 发给 AI， 看它返回的代码是否满足你的预期。

待办事项应用 prompt 模板
【角色】
你是一名_____（例如：熟悉原生 JS 的前端工程师 / 注重可访问性的 UI 开发者）。

【目标】
帮我做一个待办事项（Todo）网页，用户能够：
1. 输入任务并添加到列表
2. 标记任务为完成 / 取消完成
3. 删除任务
4. （自选）按全部 / 未完成 / 已完成筛选

【上下文】
- 目标用户是：_____
- 使用场景是：_____
- 数据不需要同步到服务器

【约束】
- 技术栈：_____
- 是否单文件：_____
- 设计风格：_____
- 必须处理的情况：_____（例如：空输入提示、本地存储兼容）

【输出要求】
- 先给出实现思路
- 再输出完整可运行的代码
- 最后列出 3 个可以进一步扩展的功能

练习步骤：

1. 先自己填好模板，不要直接复制默认内容。
2. 把 prompt 发给 AI，拿到第一版代码。
3. 检查：角色是否影响了代码风格？目标是否清晰？约束有没有被遵守？
4. 挑一个不满意的地方，用下一模块要学的方法追问修改。
