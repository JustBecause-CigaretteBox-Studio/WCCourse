第 1 小节

最早给计算机下指令的方式

今天的程序员写代码像写英文作文，但最早的计算机根本“听不懂”人话。程序员得用打孔纸带告诉机器该干什么：纸带上有孔代表 1，没孔代表 0，机器读取后执行对应动作。

这就像用摩斯电码发电报——信息密度极低，错一个孔就可能让整段程序报废。当时的程序被称为机器码，直接对应 CPU 能执行的电路开关状态，人类很难阅读和修改。

后来出现了汇编语言，用助记符代替纯数字：

汇编
; 汇编示例：把 5 和 3 相加
MOV AX, 5      ; 把 5 放进寄存器 AX
ADD AX, 3      ; 给 AX 加上 3
MOV RESULT, AX ; 把结果存到 RESULT

汇编仍然是一门“面向机器”的语言，写起来像在和 CPU 面对面打手势。但它迈出了关键一步：让人类用符号而不是二进制打孔来指挥计算机。

第 2 小节

高级语言：从“指挥机器”到“表达想法”

汇编语言还是和具体 CPU 绑得太紧。于是 1950 年代，科学家发明了高级语言：FORTRAN、COBOL、LISP 等。它们的设计目标是更接近人类的表达方式，同一段代码可以在不同机器上运行。

高级语言的核心武器是编译器或解释器。它们充当“翻译官”，把接近人话的代码转换成机器能执行的指令：

  • 编译型：先把整段代码翻译成机器码，再运行。例如 C、C++、Rust。
  • 解释型：读一行翻译一行、执行一行。例如 Python、JavaScript。

用同样的加法逻辑，C 语言只要这么写：

C
#include <stdio.h>

int main() {
    int a = 5;
    int b = 3;
    printf("%d\n", a + b);   // 直接输出 8
    return 0;
}

对比前面的汇编，C 语言不再提“寄存器”“MOV”，而是直接用变量 a、b 这样的数学符号。这就是抽象的力量：程序员专注于“做什么”，编译器负责“怎么做”。

第 3 小节

语言的进化就像搭积木

新的编程语言很少凭空出现，它们通常站在前辈的肩膀上。可以把语言发展想象成搭积木：每一层都在解决下一层的问题。

机器码是最底层的砖头，直接控制硬件但难写；汇编给机器码加了标签；C 在汇编之上又抽象出变量和函数；Python / JavaScript 则更进一步，内置了字符串、列表、字典等高级工具，让几行代码就能完成 C 几十行才能干的事。

下面用“计算 1 到 10 的和”来对比不同层级的写法：

C
// C 语言版
#include <stdio.h>
int main() {
    int sum = 0;
    for (int i = 1; i <= 10; i++) {
        sum += i;
    }
    printf("sum = %d\n", sum);
    return 0;
}
Python
# Python 版
print(sum(range(1, 11)))

Python 这一行背后，其实调用了大量 C 写成的底层代码。换句话说，Python 是站在 C 这些巨人肩膀上的“高阶语言”。

第 4 小节

综合实战：同一句话，三种语言怎么说

把本模块内容用起来

学完模块 1，我们来看看同一个“打招呼”任务在机器码、C、Python 三种层级上分别长什么样。理解这种差异，就能明白为什么高级语言让编程变得亲民。

机器码思路：把每个字符转换成 ASCII 编号，再指挥 CPU 逐字节送到屏幕输出。人类几乎无法直接阅读。

机器码
01001000 01100101 01101100 01101100 01101111   // "Hello" 的二进制 ASCII

C 语言版：编译器帮你处理字符编码和输出细节。

C
#include <stdio.h>
int main() {
    printf("Hello, world!\n");
    return 0;
}

Python 版：几乎和人说的话一样。

Python
print("Hello, world!")

从打孔纸带到高级语言，本质上是一场“让人越来越不像机器、越来越像人”的革命。你选择哪种语言，取决于你想离硬件近一点，还是想快速表达想法。
