第 1 小节

TCP：可靠的快递

前面我们说过，数据要在网络上传输。但「把数据发出去」只是第一步，接收方能不能收到、收到的顺序对不对、有没有遗漏，都需要一套规则来保证。这个规则就是传输层协议，最著名的两个是 TCP 和 UDP。

TCP（Transmission Control Protocol）像是一家严谨的快递公司。它会在发货前打电话确认对方在不在（三次握手），每到一个中转站都会签收（确认应答），如果包裹丢了会要求重发（超时重传），最后还会按编号把包裹重新摆好顺序（按序重组）。

💡 三次握手

TCP 建立连接时，客户端和服务器会交换三个包：1) 客户端「在吗？」；2) 服务器「在的，你呢？」；3) 客户端「我也在」。之后才开始正式传数据。

TCP 的优点是可靠、按顺序、不丢包，缺点是建立连接和确认应答都需要时间，延迟相对较高。网页、文件下载、邮件这些不能容忍丢数据的场景，基本都走 TCP。

在 Python 里，socket.SOCK_STREAM 就是 TCP。下面是一个最简单的 TCP 回显服务器（只监听本机）：

tcp_server.py
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("127.0.0.1", 9001))
server.listen(1)
print("TCP 服务器已启动，等待连接...")

conn, addr = server.accept()
print(f"客户端 {addr} 已连接")

while True:
    data = conn.recv(1024)
    if not data:
        break
    text = data.decode()
    print(f"收到：{text}")
    conn.sendall(f"服务器收到：{text}".encode())

conn.close()
server.close()
第 2 小节

UDP：飞鸽传书

UDP（User Datagram Protocol）和 TCP 相反，它非常「洒脱」。UDP 不建立连接，不确认收到，不保证顺序，也不重传丢包。它只管把数据包发出去，对方能不能收到它不管。

这听起来很不可靠，但正因如此，UDP 非常快。它不需要三次握手，也没有复杂的确认机制，头部开销小。直播、视频会议、在线游戏、DNS 查询这些场景常用 UDP：偶尔丢几帧画面没关系，但卡顿半秒会很明显。

TCP
面向连接、可靠、按序到达、自动重传。适合网页、文件、邮件。
UDP
无连接、不可靠、快、开销小。适合直播、游戏、语音通话。

Python 里用 socket.SOCK_DGRAM 创建 UDP socket。下面是一个 UDP 客户端的例子：

udp_client.py
import socket

# 创建一个 UDP socket
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

# 发送消息到本机的 9002 端口
message = "你好，UDP！".encode()
sock.sendto(message, ("127.0.0.1", 9002))

# 等待回复（如果对方有回复的话）
sock.settimeout(2.0)
try:
    data, addr = sock.recvfrom(1024)
    print(f"来自 {addr} 的回复：{data.decode()}")
except socket.timeout:
    print("两秒内没收到回复，UDP 不保证送达")

sock.close()

UDP 的关键字是「尽力而为」：我尽力发，但不保证到。如果你需要可靠传输，就要自己在应用层做确认和重传；如果不需要，UDP 就是更轻量的选择。

第 3 小节

动手：TCP 客户端给服务器发消息

有了 TCP 服务器，还需要一个 TCP 客户端去连接它。客户端和服务器的代码很像，只是客户端用 connect() 发起连接，然后收发数据。

运行这个练习需要两个终端：一个先运行上一节的 tcp_server.py，另一个运行下面的 tcp_client.py。客户端会连接服务器，发送一句「你好，TCP！」，然后收到服务器的回显。

tcp_client.py
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
client.connect(("127.0.0.1", 9001))  # 连接本机 9001 端口

message = "你好，TCP！"
client.sendall(message.encode())

reply = client.recv(1024).decode()
print(f"服务器回复：{reply}")

client.close()

如果先运行了服务器，再运行客户端，你会看到服务器端打印「收到：你好，TCP！」，客户端打印「服务器收到：你好，TCP！」。这就是一次完整的 TCP 请求-响应。

⚠️ 注意

服务器必须先启动，否则会报「ConnectionRefusedError」。TCP 客户端连接一个没人在监听的端口，就像敲一扇没人的门。

第 4 小节

综合实战：多人聊天室雏形

用 TCP 做一个能持续收发消息的小程序

真正的聊天软件底层也是 TCP（或类似可靠协议）。下面我们把 TCP 服务器升级一下：允许一个客户端持续输入消息，服务器收到后回显。你可以开两个客户端同时连接，观察服务器怎么处理多条连接。

为了让服务器能同时服务多个客户端，我们用 threading 给每个连接开一个新线程。这是网络编程的经典模型之一。

chat_server.py
import socket
import threading

def handle_client(conn, addr):
    print(f"[连接] {addr} 已加入")
    while True:
        try:
            data = conn.recv(1024)
            if not data:
                break
            text = data.decode()
            print(f"[来自 {addr}] {text}")
            conn.sendall(f"收到：{text}".encode())
        except Exception as e:
            print(f"[断开] {addr} {e}")
            break
    conn.close()

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("127.0.0.1", 9001))
server.listen(5)
print("聊天服务器已启动，在 127.0.0.1:9001 等待连接...")

while True:
    conn, addr = server.accept()
    t = threading.Thread(target=handle_client, args=(conn, addr))
    t.start()

客户端可以复用上一节的 tcp_client.py，也可以把它改成循环输入、持续聊天。这个练习让你体会：

1. TCP 是持续连接的，可以多次收发。

2. 服务器用多线程同时服务多个客户端。

3. 网络程序要时刻准备处理断开连接和异常。

🔑 模块 4 小结

TCP 像可靠快递，保证送达且按序；UDP 像飞鸽传书，快但不保证送达。Python 的 socket 模块可以同时创建 TCP（SOCK_STREAM）和 UDP（SOCK_DGRAM）程序。
