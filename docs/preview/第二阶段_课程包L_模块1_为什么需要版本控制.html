第 1 小节

从「最终版」到「最终最终版」的噩梦

你有没有见过这种文件夹？

论文_最终版.docx
论文_最终最终版.docx
论文_最终最终不改版.docx
论文_最终最终不改版_真的.docx
论文_最终最终不改版_真的_备份.docx

每次改动都另存为一个新文件，想找回三天前的某段文字，却根本记不清它藏在哪个「最终版」里。更可怕的是：手滑删错、改崩了、或者甲方说「还是第一版好」——全部没有后悔药。

版本控制就是来解决这个问题的。它像一台时间相机，每当你对项目做一次有意义的修改，就帮你拍一张「快照」。这些快照按顺序保存，你随时可以：

  • 回退到任意一个历史版本；
  • 查看每次改了什么；
  • 让多人同时修改而不互相覆盖。

下面这张图能帮你理解：没有版本控制时，你的文件是「一堆同名复印件」；有了版本控制，它们变成一条清晰的时间线。

第 2 小节

Git 是什么？

Git 是目前最流行的版本控制工具，免费、开源、本地运行。你可以把它理解成一个「超级记忆力助手」：

Git = 自动记录每一次修改 + 随时回滚 + 支持多人协作

Git 和手动复制文件最大的区别是：它只保存变化，而不是每次都生成一个完整副本。这样既省空间，又能精确告诉你「谁在什么时候改了哪一行」。

使用 Git 时，你主要和三个概念打交道：

  • 工作区（Working Directory）：你日常看到的文件夹；
  • 暂存区（Stage/Index）：准备提交的快照；
  • 仓库（Repository）：保存所有历史版本的地方。

简单记忆：工作区是你正在写字的草稿纸，暂存区是准备交的作业，仓库是老师收上去归档的档案袋。

第 3 小节

安装与初次配置

在开始学习具体命令前，先确保电脑里已经安装了 Git。打开终端（Windows 用 Git Bash 或 PowerShell，macOS 用 Terminal），输入：

git --version

如果看到类似 git version 2.40.0 的输出，说明已经装好了。没有的话，去 git-scm.com 下载安装。

安装好后，先告诉 Git 你是谁。这一步只需要做一次：

git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"

这些信息会写在每一次提交记录里，方便日后追溯「这段代码是谁写的」。可以用下面的命令检查是否配置成功：

git config --global user.name
git config --global user.email
第 4 小节

综合实战

手动做一次「土法版本控制」

在真正用 Git 之前，先用最朴素的方式体验一下「版本控制」到底解决什么问题。请准备一个小项目文件夹，里面放一篇作文或一段代码。

步骤 1：写第一版内容并保存。

步骤 2：修改几个句子后，把文件另存为 作文_第2版.txt。

步骤 3：再改一次，另存为 作文_第3版.txt。

步骤 4：尝试回答：如果老师说「把第二段改回第一版的样子」，你能立刻找到吗？三个文件分别占了多少空间？

做完这个小练习，你应该能体会到：手动复制文件既混乱又浪费。下一模块开始，我们用 Git 把这套流程自动化。
