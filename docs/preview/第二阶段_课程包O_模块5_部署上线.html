第 1 小节

为什么需要部署

到目前为止，我们写的网页都保存在本地电脑上，只有你自己能打开。要让朋友、家人或全世界的人看到，就需要把网页文件放到一台24 小时不关机的服务器上，这个过程就叫「部署」。

部署方式大体分两类：

  • 静态网站托管：只包含 HTML、CSS、JS、图片等文件，不需要服务器实时计算。适合个人博客、作品集、宣传页。
  • 动态应用托管：需要服务器运行 Python 等程序，根据用户输入实时生成内容。适合 BMI 计算器、数据看板、后台系统。

本模块的静态网站用 GitHub Pages，动态 Streamlit 应用用 Streamlit Cloud。两者都有免费额度，对新手非常友好。

第 2 小节

GitHub Pages

GitHub Pages 是 GitHub 提供的免费静态网站托管服务。只要你把 HTML 文件推送到 GitHub 仓库，再开启 Pages 功能，就能得到一个公开的网址。

操作步骤：

  1. 在 GitHub 上新建一个仓库，比如 my-portfolio。
  2. 把网页文件上传到仓库，确保仓库根目录有 index.html。
  3. 进入仓库的 Settings → Pages。
  4. 在 Branch 选项里选择 main 分支，保存。
  5. 等待 1-2 分钟，浏览器访问 https://你的用户名.github.io/my-portfolio。

一个最小的仓库结构如下：

静态网站仓库结构
my-portfolio/
├── index.html
├── style.css
├── script.js
└── images/
    └── avatar.png

GitHub Pages 适合个人作品集、项目演示页和文档站点。它只托管静态文件，不能运行 Python 代码。

第 3 小节

Streamlit Cloud

如果你做的是 Streamlit 应用，就需要一台能运行 Python 的服务器。Streamlit Cloud 可以直接读取你的 GitHub 仓库，自动安装依赖并运行应用。

操作步骤：

  1. 把 app.py 放到 GitHub 仓库根目录。
  2. 如果用了第三方库，在仓库里放一个 requirements.txt，里面列出库名。
  3. 访问 share.streamlit.io，用 GitHub 账号登录。
  4. 选择对应的仓库，点击 Deploy。

一个典型的 Streamlit 仓库结构：

Streamlit 仓库结构
my-bmi-app/
├── app.py
└── requirements.txt

requirements.txt 示例：

requirements.txt
streamlit==1.40.0

部署完成后，你会得到一个类似 https://my-bmi-app-xxx.streamlit.app 的网址，把它发给朋友就能直接使用。

第 4 小节

综合实战

把你的 BMI 计算器或作品集发布到网上

选一个你在前面模块完成的项目，把它真正发布出去。这里给出两条路线，你可以根据项目类型选择。

路线 A：静态作品集网页（用 GitHub Pages）

  1. 整理模块 6 要做的作品集页面，确保入口文件叫 index.html。
  2. 把文件推送到 GitHub 仓库。
  3. 开启 GitHub Pages，等待网站上线。

路线 B：Streamlit 应用（用 Streamlit Cloud）

  1. 把模块 4 的 bmi.py 重命名为 app.py。
  2. 添加 requirements.txt 并写上 streamlit。
  3. 把文件推送到 GitHub 仓库。
  4. 在 Streamlit Cloud 上选择仓库并部署。

实战任务：

  • 注册一个 GitHub 账号（如果还没有）。
  • 创建仓库，上传文件。
  • 完成部署后，把链接复制到浏览器打开，确认能正常访问。
  • 把链接发给一个朋友，让他也看一看。
