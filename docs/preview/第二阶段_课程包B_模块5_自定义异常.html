第 1 小节

为什么需要自定义异常

Python 自带的异常已经很多，但有时候你的程序有自己的"业务规则"。比如游戏角色血量不能为负、年龄不能超过 150、密码长度必须大于 6……

这些不是 Python 的语法错误，而是你定义的语义错误。用自定义异常，可以让错误信息更贴合你的程序，也让调用者更容易理解哪里出了问题。

# 直接用通用异常也能跑，但别人看不懂是什么意思
if hp < 0:
    raise Exception("血量不能为负数")  # 太笼统

如果改成 NegativeHPError，一看就知道是"血量异常"。

第 2 小节

用 class 定义自己的异常

自定义异常很简单：写一个类，继承 Python 的 Exception 即可。名字通常以 Error 结尾，让人一看就知道这是异常。

class NegativeHPError(Exception):
    """血量不能为负数"""
    pass

class TooYoungError(Exception):
    """年龄太小"""
    pass

类体里写 pass 就够了，因为所有异常机制都从 Exception 继承而来。你当然可以加上自己的初始化逻辑，让错误信息更丰富。

第 3 小节

raise：主动抛出异常

定义好异常后，用 raise 主动"扔"出它。这通常放在函数开头做参数检查，也叫"防御式编程"。

class NegativeHPError(Exception):
    pass

def set_hp(hp):
    if hp < 0:
        raise NegativeHPError(f"血量不能为负，你传了 {hp}")
    print(f"血量设置为 {hp}")

try:
    set_hp(-10)
except NegativeHPError as e:
    print("捕获到自定义异常：", e)

主动抛出异常不是坏事，它让错误越早发现越好，避免带着脏数据继续跑，最后更难调试。

第 4 小节

综合实战：游戏角色校验

给游戏角色系统加上自定义异常：血量不能为负，年龄必须在 0~120 之间。写一个 create_player 函数，传入 name、age、hp，参数不合法就抛出自定义异常。

class NegativeHPError(Exception):
    pass

class InvalidAgeError(Exception):
    pass

def create_player(name, age, hp):
    if age < 0 or age > 120:
        raise InvalidAgeError("年龄必须在 0~120 之间")
    if hp < 0:
        raise NegativeHPError("血量不能为负数")
    return {"name": name, "age": age, "hp": hp}

try:
    player = create_player("勇者", 200, 100)
    print(player)
except InvalidAgeError as e:
    print("创建失败：", e)
except NegativeHPError as e:
    print("创建失败：", e)

你可以把 age 改成负数、hp 改成负数，分别测试两个异常是否能被正确捕获。
