第 5 章 · 调试与排错

当程序不听话——调试与排错

零基础的人，80% 的挫败感来自报错。 但报错不是惩罚，而是电脑在努力告诉你它哪里没听懂。 这一章把「恐惧」变成「线索」。

开始第 1 小节 → 5 个小节 · 约 20 分钟 · 学会和 bug 和平共处
第 1 小节

为什么程序会不听话

把恐惧变成线索

很多初学者第一次遇到报错时，会害怕是自己「不适合学编程」。 其实报错只是电脑在很努力地告诉你，它哪里没听懂。

写程序和教外国人学中文有点像。你说的每句话，对方都会照字面执行；

研表究明，汉字序顺并不影阅响读。

但外国人会觉得有影响，一旦某个词发音不对或语序混乱，对方就会停下来，指着那个词说：「这里我没听懂。」

🔑 调试（Debug）是什么

调试就是找出程序为什么没有按你的想法执行，然后把它改对。

报错信息不是判决，而是线索。学会读线索，你就已经赢过 80% 的初学者。

🌱 先记住这一句话

bug是电脑的问题，不是你的问题。

第 2 小节

报错信息不是天书

如何读报错信息

报错信息通常由两部分组成： 它在哪里出错（行号）和 它为什么出错（错误类型 + 简短说明）。 只要找到这两样，你就已经有了排查方向。

常见的报错长什么样

下面是一段 C++ 的语法错误。注意看报错最后一行：它指出了第 4 行，还告诉你漏了分号。

下面是一段 Python 的语法错误。注意看报错最后一行：它指出了第 3 行，还告诉你 if 后面漏了冒号。

#include <iostream>
using namespace std;

int main() {
    cout << "Hello"    // 这里漏了分号
    return 0;
}
name = "小白"
if name == "小白"
    print("你好，小白")
💥 报错信息（节选）
main.cpp: In function 'int main()':
main.cpp:4:5: error: expected ';' before 'return'
    4 |     return 0
      |     ^~~~~~
  File "main.py", line 3
    if name == "小白"
                    ^
SyntaxError: expected ':'

读报错的技巧：

1. 先看行号
它说哪里，你就先看哪里

行号通常很准；如果不对，它指的地方一般也在附近。

2. 再看错误类型
Syntax / Name / Type / Runtime

类型能告诉你问题的性质：语法、名字、类型还是运行中出错。

💡 小秘诀

C++ 报错往往很长，重点看最后几行。

Python 报错通常比较短，从上到下读即可。

小试牛刀：看到报错信息时，最应该先关注什么？
💡 小知识

一些前端开发者（写网页的人）由于代码习惯不好，在制作大型项目（如游戏）时，会出现「报错信息指向的行号和实际出错的行号不一致」的情况。 这是因为有一种变量类型any，它可以存储任何类型的值，如果这种变量装错了东西，例如装了字符又与数字做运算，报错信息可能会指向它的定义行，而不是实际出错的行，这得让人掉不少头发。 可以问问AI为什么要有Typescript这种语言，它就是为了解决这个问题的。

第 3 小节

print() 是最强的调试器

逐行追踪变量

程序不会说话时，你要帮它说话。在关键位置把变量打印出来， 你就能亲眼看到程序每一步在想什么。

一个例子：算式为什么结果不对

我们想算 1 到 5 的和，但 C++ 程序算错了。先加上 cout 看看变量每一步的值。

我们想算 1 到 5 的和，但 Python 程序算错了。先加上 print 看看变量每一步的值。

#include <iostream>
using namespace std;

int main() {
    int total = 0;
    for (int i = 1; i <= 5; i++) {
        total = total + i;
        cout << "i = " << i << ", total = " << total << endl;
    }
    cout << "最终 total = " << total << endl;
    return 0;
}
total = 0
for i in range(1, 6):
    total = total + i
    print("i =", i, ", total =", total)
print("最终 total =", total)
✅ 输出结果
i = 1, total = 1
i = 2, total = 3
i = 3, total = 6
i = 4, total = 10
i = 5, total = 15
最终 total = 15

如果某一步的 total 突然变成了奇怪的值，比如 total = 0 一直不变， 你就能立刻定位：原来是我把 total = total + i 写成了 total = i。

🔑 调试技巧

看不懂就打印，想不通就打印，程序越怪越要打印。

🛠️ 动手任务

打开你之前写的任意一段 C++ 代码，或者自己写一段（例如 1+2+……+100），在循环里加一行 cout，看看变量每一步是不是你想象的样子。

打开你之前写的任意一段 Python 代码，或者自己写一段（例如 1+2+……+100），在循环里加一行 print()，看看变量每一步是不是你想象的样子。

第 4 小节

三种常见的 bug

语法错误、逻辑错误、运行时错误

大部分 bug 可以归为三类。知道是哪一类，你就知道该用什么工具对付它。

1. 语法错误（Syntax Error）

程序连启动都没启动就报错。通常是标点、拼写、括号、冒号、分号出了问题。

C++ 常见

漏了分号 ;

括号不匹配 {} ()

字符串引号没成对

Python 常见

漏了冒号 :

缩进不对

括号不匹配

2. 运行时错误（Runtime Error）

语法没问题，程序能启动，但运行到某一行时突然崩溃。 常见原因：除以零、访问不存在的列表位置、类型不匹配。 

#include <iostream>
using namespace std;

int main() {
    int a = 10;
    int b = 0;
    cout << a / b;    // 运行时错误：除以零
    return 0;
}
numbers = [1, 2, 3]
print(numbers[10])   # 运行时错误：索引越界

3. 逻辑错误（Logic Error）

程序能运行，也不报错，但结果不是你想要的。这是最难发现的 bug， 也是 print() 调试最能派上用场的地方。 

// 想算 1 到 5 的平均值，但结果错了
#include <iostream>
using namespace std;

int main() {
    int sum = 1 + 2 + 3 + 4 + 5;    // sum = 15
    int average = sum / 5;          // 这里是 3，不是 3.0
    cout << average << endl;       // 如果期望 3.0，就是逻辑错误
    return 0;
}
# 想算 1 到 5 的平均值，但结果错了
sum = 1 + 2 + 3 + 4 + 5    # sum = 15
average = sum / 5          # Python 里结果是 3.0，没问题
# 但如果写成 sum // 5，结果就变成 3，这就是逻辑错误
print(average)

第 5 小节

遇到 bug 时，怎么向 AI 描述问题

最快得到答案的方法

AI 很强，但它不会读心术。你描述得越清楚，它定位 bug 的速度就越快。 最有效的方法不是直接说「这里错了」，而是给它一个完整的「病历」。

🔑 描述 bug 的万能模板

1. 我想做什么：我希望程序输出……
2. 实际发生了什么：它输出了…… / 它报错了……
3. 报错信息：把完整报错粘贴进来（不要只贴一半）。
4. 相关代码：把和错误相关的片段贴进来。
5. 我试过的方法：我改了哪里、加了什么 print、结果如何。

下面是一份可以直接复制发给 AI 的模板：

请帮我 debug 这段代码。

【目标】
我想让程序实现：

【实际结果】
程序运行后：
- 如果是报错：把完整的报错信息粘贴到这里
- 如果是结果不对：写出实际输出

【相关代码】
```
把和错误相关的代码贴在这里
```

【我试过的方法】
- 我已经检查过……
- 我在第 X 行附近加了 print，发现变量值是……
- 我怀疑问题可能在……

请帮我指出 bug 在哪里，并告诉我为什么这么改。

几个让 AI 更快理解的小技巧

✅ 这样做

贴完整报错，包括行号

只贴相关代码，不要太长

说明你想要什么结果

告诉 AI 你用的语言是 C++ 还是 Python

❌ 避免这样

只说「代码报错了」

一次性把整个文件贴上去

报错只截最后半句

不说明你期望的结果

当然，如果遇到一些一眼能看出来的简单的报错，例如教程演示里的缺分号/冒号，你也可以动动手指自己改。

并且，建议先用免费的网页对话进行debug，使用“复制、粘贴、问AI”几种方法，解决不了再去用Agent。
