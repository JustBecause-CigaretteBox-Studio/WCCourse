第 1 小节

为什么大项目会乱

没有分类的图书馆

小项目可以所有代码塞一个文件，但项目一大，问题就来了： 函数找不到、变量重名、改一个地方坏三个地方。

想象你走进一座图书馆，所有书都堆在地上，没有分类、没有编号。 你想找一本《Python 入门》，可能要翻一整天。 项目文件也是同样的道理： 没有组织的代码，就是堆在地上的书。

混乱项目示例
project/
├── a.js
├── b.js
├── test.html
├── old.html
├── backup.js
├── script_final.js
├── script_final2.js
└── todo.txt

你能看出哪个文件是当前在用的吗？这种混乱会让 AI 也迷失： 你让它「在 script_final2.js 里加功能」，它可能改错文件。

架构思维的第一步，就是给项目定规矩：文件放哪里、叫什么、谁负责什么。 规矩定好了，AI 才能更好地帮你维护。

看一个真实的例子

下面是作者自己的游戏项目的目录结构截图。可以看到，所有资源按“职责”分门别类，每个文件夹管一类事：

第 2 小节

分层：给代码分房间

数据、逻辑、界面各司其职

分层是最基础也最有效的架构思想。它的核心就是： 不同职责的代码放到不同的地方。

一个常见的 Web 小项目可以分成三层：

三层结构示例
project/
├── index.html          # 页面结构（界面层）
├── css/
│   └── style.css       # 样式（表现层）
├── js/
│   ├── main.js         # 入口：初始化、绑定事件
│   ├── ui.js           # 界面渲染：操作 DOM
│   ├── data.js         # 数据管理：读写 localStorage
│   └── logic.js        # 业务逻辑：计算、校验
└── README.md           # 项目说明

每一层的职责：

各层职责
界面层（HTML/CSS）：
- 负责用户看到的东西
- 不关心数据从哪里来

业务逻辑层（logic.js）：
- 负责计算、校验、判断
- 不直接操作 DOM

数据层（data.js）：
- 负责存取数据
- 不关心数据怎么用

分层的好处是：改样式不会动到逻辑，换存储方式不会动到界面。 告诉 AI 你的分层规则，它就不会把所有代码挤在一个文件里。

让 AI 分层的 prompt
请按以下结构实现一个待办事项应用：
- index.html：只放页面结构和引入 CSS/JS
- css/style.css：所有样式
- js/data.js：负责 localStorage 的读写
- js/logic.js：负责任务增删改查的业务逻辑
- js/ui.js：负责渲染列表和绑定事件
- js/main.js：入口，初始化应用

每个文件只负责自己的事，不要互相越界。
第 3 小节

用 AI 维护项目结构

目录、迁移、文档

AI 不仅能写代码，还能帮你维护项目结构。 当你想新增功能、重构文件或迁移代码时，可以把它当作一个「架构助手」。

1. 生成目录结构

目录 prompt 示例
我要做一个"个人博客"前端项目，请给我推荐一个清晰的目录结构。
要求：
- 使用原生 HTML + CSS + JS
- 包含首页、文章页、关于页
- 文章数据用 JSON 文件模拟
- 样式要支持深色模式

请用树状图输出目录，并说明每个文件/文件夹的职责。

2. 迁移和重构

当项目变大时，你可能需要把一个大文件拆成几个小文件。 直接让 AI 帮你做迁移，并给出迁移后的目录。

重构 prompt 示例
我的项目现在所有 JS 都在一个 app.js 文件里，很乱。
请帮我把它拆分成：
- main.js（入口）
- router.js（路由）
- api.js（模拟数据请求）
- render.js（渲染逻辑）

请输出每个新文件应该包含哪些函数，并给出迁移步骤。

3. 写 README

README 是项目的"说明书"。让 AI 根据代码生成 README，能帮你理清项目结构，也方便以后回顾。

README prompt 示例
请根据下面的项目结构生成一份 README.md，
包含：项目简介、目录说明、如何运行、技术栈、后续可扩展功能。

[粘贴你的项目结构]

维护结构比写代码更需要全局观。把这类任务交给 AI，你可以把精力放在业务逻辑上。

第 4 小节

综合实战：为一个博客系统设计文件结构

从需求推导出清晰的目录

现在动手设计一个「个人博客系统」的文件结构。不需要写代码，重点是让 AI 和你一起规划清楚架构。

需求：

博客系统需求
功能：
- 首页展示文章列表
- 文章详情页展示正文
- 关于页介绍作者
- 深色/浅色主题切换
- 文章数据暂时用 JSON 文件模拟

技术要求：
- 原生 HTML + CSS + JS
- 单页应用（切换页面不刷新）
- 移动端适配

后续可能扩展：
- 文章分类和标签
- 评论功能
- 搜索功能

任务：

你的 prompt
我要做一个个人博客系统，技术栈是原生 HTML + CSS + JS。
请帮我设计项目目录结构，要求：
1. 代码按职责分层（页面、样式、数据、逻辑、工具）
2. 支持首页、文章详情页、关于页
3. 文章数据用 JSON 模拟
4. 预留分类、评论、搜索的扩展空间

请用树状图输出目录，并说明每个文件/文件夹的职责。

检查清单：

验收标准
□ 是否能一眼看出 HTML、CSS、JS 分别放在哪里？
□ 数据文件是否和逻辑文件分开？
□ 是否有明确的入口文件？
□ 是否给未来扩展留了位置？
□ README 是否说明了如何运行？

把 AI 生成的结构和你自己想的对比一下，讨论哪一种更适合你的需求。 这个练习让你学会用架构视角看项目，而不是只盯着一行行代码。
