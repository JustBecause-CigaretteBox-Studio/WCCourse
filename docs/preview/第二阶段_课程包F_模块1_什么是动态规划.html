第 1 小节

动态规划是什么

你放学回家，学校（A）到家(D)之间是一张密密麻麻的街道网。你想找一条最短的路线。

一种暴力的办法：站在学校门口，逐个枚举所有可能的路线。然而，不同路线经常会在某个路口"撞车"——例如路线 A-C-B-D 和路线 A-E-B-D 中，两条路线在 B"撞车"后，接下来的问题一模一样："从 B 这个路口到家（D），怎么走最近？"但暴力算法不管这些，有多少条在 B"撞车"的路线，它就把这个路口（B）之后的所有可能性，分别重新计算多少次。

这时候你发现了两个事情：

第一个事情叫"重叠子问题"。"从学校到家"这个大问题，其实是由无数个小问题拼成的："从 B 路口到家""从 C 路口到家"……而且这些小问题会反复出现。站在 A 路口时，要算"A 到家"；站在 B 路口时，某条路线也可能绕回 A 路口，于是又要算一遍"A 到家"。这些子问题不断堆叠、重复。

第二个事情叫"最优子结构"。假设你已经知道了"从 A 路口到家最短是 2 公里"。那么当你站在 A 路口的邻居——B 路口时，如果 B 到 A 只有 300 米，你立刻就能确定：所有 B 到家且经过 A 的条路线一定不少于 2.3 公里。A 路口的最优解，直接成为了 B 路口最优解的一块积木。换句话说，大问题最优解的其中一块，一定是某个小问题的最优解。

所以聪明的做法是：你带了一叠便利贴，从家反向往外走。每到一个新路口，你算出它到家的最短距离，写在便利贴上，贴在路牌背后。下次只要你又站到了这个路口，看一眼便利贴就能知道答案。

这些便利贴上的数字，就是状态。你填便利贴的顺序，就是状态转移。而"从家反向推"这个思路，就是递推。在编程里，"写便利贴"通常用数组或字典实现，称为记忆化或填表。动态规划不是某种具体的算法，而是一种解题思想：把大问题拆成相似的小问题，把小问题的答案存起来，避免重复计算。

dp_idea.py
# 动态规划的核心：先算小问题，再拼大问题
# 例如：计算 1+2+3+...+n
# 我们记下 "前 i 项的和"，而不是每次都从 1 开始加

def sum_dp(n):
    dp = [0] * (n + 1)      # dp[i] 表示 1 到 i 的和
    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + i  # 小答案拼成大答案
    return dp[n]

print(sum_dp(10))  # 55
dp_idea.cpp
// 动态规划的核心：先算小问题，再拼大问题
// 例如：计算 1+2+3+...+n
// 我们记下 "前 i 项的和"，而不是每次都从 1 开始加
#include <iostream>
#include <vector>
using namespace std;

int sum_dp(int n) {
    vector<int> dp(n + 1, 0);   // dp[i] 表示 1 到 i 的和
    for (int i = 1; i <= n; ++i) {
        dp[i] = dp[i - 1] + i;  // 小答案拼成大答案
    }
    return dp[n];
}

int main() {
    cout << sum_dp(10) << endl;  // 55
    return 0;
}
第 2 小节

能用 DP 解决的问题长什么样

不是所有问题都能用动态规划解决。一个题目适合用 DP，通常具备下面两个特征：

1. 重叠子问题（Overlapping Subproblems）：大问题拆成的小问题会反复出现。比如算斐波那契数列时，fib(5) 需要 fib(4) 和 fib(3)，而 fib(4) 又需要 fib(3)。如果不记下来，fib(3) 会被算很多次。

2. 最优子结构（Optimal Substructure）：大问题的最优解可以由小问题的最优解组合得到。比如"从学校到家的最短路线"，一定是从学校到某个邻居路口的最短路线再加上那个路口到家的最短路线，或者直接从学校到家的路线。

换个生活化的类比：做一道复杂的菜时，如果每切一种配料都重新洗刀、洗菜板，就很慢；DP 就像先把所有配料洗好切好装在小碗里，炒菜时直接拿。只要配料（子问题）会被多次用到，先准备好就能省很多时间。

fib_naive.py
# 普通递归：大量重复计算
# 计算 fib(5) 时，fib(2) 会被计算 3 次

def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(5))   # 5
print(fib(30))  # 832040（已经有点慢了）
fib_naive.cpp
// 普通递归：大量重复计算
// 计算 fib(5) 时，fib(2) 会被计算 3 次
#include <iostream>
using namespace std;

int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

int main() {
    cout << fib(5) << endl;   // 5
    cout << fib(30) << endl;  // 832040（已经有点慢了）
    return 0;
}
第 3 小节

把答案记下来：记忆化入门

解决重叠子问题最直接的办法，就是加一个"备忘录"。在 Python 里，可以用字典或列表当备忘录；在 C++ 里，可以用数组或 unordered_map 当备忘录；计算某个子问题之前先查表，算完之后把结果写进表。

下面用 fib_memo 演示：第一次调用 fib(10) 时，会把 fib(0) 到 fib(10) 全部算一遍并保存；之后再访问已经算过的值，直接返回，几乎是瞬间完成。当 n 达到 50 甚至 1000 时，这种差别会极其明显。

fib_memo.py
# 记忆化递归：把算过的结果存起来
memo = {}

def fib_memo(n):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1) + fib_memo(n - 2)
    return memo[n]

print(fib_memo(50))   # 12586269025（普通递归会卡很久）
print(fib_memo(100))  # 354224848179261915075
fib_memo.cpp
// 记忆化递归：把算过的结果存起来
#include <iostream>
#include <vector>
using namespace std;

vector<long long> memo;

long long fib_memo(int n) {
    if (memo[n] != -1) return memo[n];
    if (n <= 1) return n;
    memo[n] = fib_memo(n - 1) + fib_memo(n - 2);
    return memo[n];
}

int main() {
    memo.assign(101, -1);
    cout << fib_memo(50) << endl;   // 12586269025（普通递归会卡很久）
    cout << fib_memo(100) << endl;  // 354224848179261915075
    return 0;
}

观察上面的代码：memo 就是那张"便利贴"。每次进入函数，先看便利贴上有没有答案；没有才算，算完贴上去。这个模式在 DP 里会反复出现，建议你把它记熟。

第 4 小节

综合实战：青蛙跳台阶

从递归到记忆化

一只青蛙站在第 0 级台阶上，每次可以跳 1 级或 2 级。问到第 n 级台阶有多少种不同的跳法？

先想递归思路：要到第 n 级，最后一步要么从第 n-1 级跳上来，要么从第 n-2 级跳上来。所以 ways(n) = ways(n-1) + ways(n-2)。边界是 ways(0)=1（原地不动算一种），ways(1)=1。

这个关系和斐波那契几乎一样，也有大量重叠子问题。我们用字典（哈希表）做记忆化，我们用数组或 unordered_map 做记忆化，把它改写成高效的版本。你也可以尝试改成自底向上循环的版本，体会"填表"的感觉。

frog_jump.py
# 青蛙跳台阶：记忆化递归版
cache = {}

def ways(n):
    if n in cache:
        return cache[n]
    if n == 0 or n == 1:
        return 1
    cache[n] = ways(n - 1) + ways(n - 2)
    return cache[n]

n = int(input("请输入台阶数 n："))
print(f"跳到第 {n} 级共有 {ways(n)} 种方法")

# 提示：创建一个 dp 数组，dp[i] 表示跳到第 i 级的方法数
