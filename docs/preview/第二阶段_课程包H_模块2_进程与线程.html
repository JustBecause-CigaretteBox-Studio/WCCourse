第 1 小节

进程：程序的“一次执行”

当你双击打开一个程序，操作系统会创建一个新的进程（Process）。进程就是“运行中的程序”：它有自己的内存空间、代码、数据和当前执行到的位置。

每个进程都有一个唯一的编号，叫做 PID（Process ID）。你可以通过 PID 来查找、暂停或结束一个进程。在 Windows 任务管理器或 Linux 的 ps 命令里，PID 都是最常见的列之一。

进程之间默认是隔离的：一个进程崩溃，通常不会直接影响另一个进程。这也是现代系统稳定性的重要来源。

process_demo.py
import os

# 当前进程自己的 PID
print("我的 PID：", os.getpid())

# 父进程的 PID（启动当前进程的进程）
print("父 PID：", os.getppid())
process_demo.cpp
#include <iostream>
#ifdef _WIN32
#include <windows.h>
#else
#include <unistd.h>
#endif

int main() {
#ifdef _WIN32
    std::cout << "我的 PID： " << GetCurrentProcessId() << std::endl;
    std::cout << "父 PID： （Windows 需额外查询）" << std::endl;
#else
    std::cout << "我的 PID： " << getpid() << std::endl;
    std::cout << "父 PID： " << getppid() << std::endl;
#endif
    return 0;
}
第 2 小节

线程：进程里的“小工人”

一个进程可以包含多个线程（Thread）。如果把进程比作一家工厂，线程就是工厂里的工人。它们共享同一间厂房（进程的内存空间），但各自执行不同的任务。

线程比进程更轻量：创建和切换线程的成本更低，因为它们不需要复制整个内存空间。但共享内存也意味着一个线程出错，可能影响同一进程里的其他线程。

多线程常用于：同时处理用户界面和后台计算、同时下载多个文件、并行处理数据等。

thread_demo.py
import threading

def say_hello(name):
    print(f"线程 {name} 说：你好！")

# 创建两个线程
t1 = threading.Thread(target=say_hello, args=("A",))
t2 = threading.Thread(target=say_hello, args=("B",))

t1.start()
t2.start()

t1.join()
t2.join()

print("两个线程都执行完了")
thread_demo.cpp
#include <iostream>
#include <thread>
#include <string>

void sayHello(const std::string &name) {
    std::cout << "线程 " << name << " 说：你好！" << std::endl;
}

int main() {
    std::thread t1(sayHello, "A");
    std::thread t2(sayHello, "B");

    t1.join();
    t2.join();

    std::cout << "两个线程都执行完了" << std::endl;
    return 0;
}
第 3 小节

并发与并行

并发（Concurrency）和并行（Parallelism）听起来很像，其实是两个概念。

并发是指“看起来同时做很多事”：操作系统快速切换线程，让它们交替执行。单核 CPU 也能实现并发。并行是指“真正同时做很多事”：多核 CPU 同时执行多个线程。

一个经典类比：并发是一个人同时吃三碗饭；并行是三个人同时吃三碗饭。

concurrency_demo.py
import threading
import time

def cook(name, seconds):
    print(f"{name} 开始制作，需要 {seconds} 秒")
    time.sleep(seconds)
    print(f"{name} 制作完成")

# 并发：两个任务交替进行
start = time.time()
t1 = threading.Thread(target=cook, args=("煮面", 2))
t2 = threading.Thread(target=cook, args=("煎蛋", 1))

t1.start(); t2.start()
t1.join();  t2.join()

print(f"总共耗时：{time.time() - start:.2f} 秒")
concurrency_demo.cpp
#include <iostream>
#include <thread>
#include <chrono>

void cook(const std::string &name, int seconds) {
    std::cout << name << " 开始制作，需要 " << seconds << " 秒" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(seconds));
    std::cout << name << " 制作完成" << std::endl;
}

int main() {
    auto start = std::chrono::steady_clock::now();

    std::thread t1(cook, "煮面", 2);
    std::thread t2(cook, "煎蛋", 1);

    t1.join();
    t2.join();

    auto end = std::chrono::steady_clock::now();
    auto elapsed = std::chrono::duration_cast<std::chrono::seconds>(end - start).count();
    std::cout << "总共耗时：" << elapsed << " 秒" << std::endl;
    return 0;
}
第 4 小节

并发一定更快吗？——响应性与速度的真相

破除“多线程 = 自动变快”的迷思

很多新手以为：开了多线程，程序就自动变快了。这是一个常见误解。并发的核心价值是“提高响应性”，而不一定是“提高计算速度”。

并发是怎么“看起来”同时进行的？ 在单核 CPU 上，操作系统通过快速切换线程（上下文切换）让多个任务交替执行。切换足够快，人（甚至程序逻辑）就以为它们在同时进行。这种“看起来同时”就是并发——它解决的是“等待”和“响应”的问题，而不是“算得更快”。

✅ 什么情况下，并发真的会提高效率？

  • I/O 密集型任务：当一个任务在等待网络或磁盘时，CPU 立刻切换到另一个任务去执行，减少空闲等待，提高资源利用率。
  • 提升系统响应性：界面在后台计算时仍能响应用户的点击，不会“卡死”假死。

⚠️ 什么情况下，并发不会提高效率，甚至更慢？

  • CPU 密集型任务：频繁的上下文切换本身就有开销（保存/恢复寄存器、缓存失效）。如果任务全是计算，切换反而浪费 CPU 周期。
  • 单核上的纯计算：并发执行两个计算任务，总时间往往比串行更长——切换开销叠加，却没有真正并行的计算资源。

下面用“多任务下载模拟器”体会第一种情况。这里的“下载”用 time.sleep 模拟等待网络——这正是 I/O 密集型场景：线程在“等”的时候，CPU 可以去干别的，所以并发把多段等待重叠起来，总时间接近最慢的那个任务，而不是所有任务耗时相加。

download_sim.py
import threading
import time

def download(file, size):
    print(f"开始下载 {file}（大小 {size} MB）")
    time.sleep(size * 0.1)  # 每 MB 模拟 0.1 秒
    print(f"下载完成：{file}")

files = [("a.zip", 5), ("b.mp4", 8), ("c.pdf", 3)]

start = time.time()
threads = []
for name, size in files:
    t = threading.Thread(target=download, args=(name, size))
    t.start()
    threads.append(t)

for t in threads:
    t.join()

print(f"全部完成，耗时 {time.time() - start:.2f} 秒")
download_sim.cpp
#include <iostream>
#include <thread>
#include <chrono>
#include <vector>
#include <string>

void download(const std::string &file, int size) {
    std::cout << "开始下载 " << file << "（大小 " << size << " MB）" << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(size * 100));
    std::cout << "下载完成：" << file << std::endl;
}

int main() {
    std::vector<std::pair<std::string, int>> files = {
        {"a.zip", 5},
        {"b.mp4", 8},
        {"c.pdf", 3}
    };

    auto start = std::chrono::steady_clock::now();
    std::vector<std::thread> threads;
    for (auto &f : files) {
        threads.emplace_back(download, f.first, f.second);
    }

    for (auto &t : threads) {
        t.join();
    }

    auto end = std::chrono::steady_clock::now();
    double elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count() / 1000.0;
    std::cout << "全部完成，耗时 " << elapsed << " 秒" << std::endl;
    return 0;
}

试着把线程版本改成顺序执行（去掉线程，直接调用 download）对比耗时——你会看到并发更快。但注意：这里的“快”来自等待时间的重叠，并不是计算被加速。如果把 time.sleep 换成一串纯计算（比如大数求和），在单核上多线程反而会更慢，正是上面第二个坑。
