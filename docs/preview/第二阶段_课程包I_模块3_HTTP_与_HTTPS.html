第 1 小节

HTTP：浏览器和服务器之间的对话

当你在浏览器输入一个网址并按下回车，浏览器会向服务器发送一条 HTTP 请求（Request）；服务器收到后，返回一条 HTTP 响应（Response）。浏览器根据响应内容把网页渲染出来。整个过程就像你去餐厅点餐：你说「我要一份牛肉面」（请求），服务员把面端上来（响应）。

HTTP 请求里最重要的几个部分是：方法（Method）、路径（Path）、请求头（Headers）和请求体（Body）。最常用的两个方法是 GET 和 POST：GET 用来「获取」资源，POST 用来「提交」数据。

GET
向服务器要东西。参数放在 URL 后面，比如 /search?q=python。
POST
向服务器提交东西。参数放在请求体里，比如登录表单、发表评论。

下面用 Python 标准库的 urllib.request 发起一次简单的 GET 请求。注意：这段代码需要联网。

simple_get.py
from urllib.request import urlopen

# 向 example.com 发送 GET 请求
url = "https://www.example.com"
response = urlopen(url)

print("状态码：", response.status)          # 200 表示成功
print("内容类型：", response.headers.get("Content-Type"))
print("\n网页前 300 字符：")
print(response.read(300).decode("utf-8"))

如果网络正常，你会看到状态码 200，以及网页的 HTML 开头。200 是 HTTP 状态码的一种，表示「一切正常」。后面我们会见到更多状态码。

第 2 小节

状态码、响应头与响应体

HTTP 响应也分成三部分：状态行（协议版本 + 状态码 + 状态文本）、响应头（描述响应的元数据）和响应体（真正的内容，比如 HTML、图片、JSON）。

状态码是三位数字，按首位分成几类：

2xx 成功
200 OK 最常见；201 Created 表示新建成功。
3xx 重定向
301/302 表示资源搬家了，浏览器要跳转到新地址。
4xx 客户端错误
404 Not Found 最常见；400 Bad Request 是请求格式不对。
5xx 服务器错误
500 Internal Server Error；503 Service Unavailable。

响应头里有很多有用信息。比如 Content-Type 告诉你响应体是 HTML、JSON 还是图片；Content-Length 告诉你内容有多长；Set-Cookie 让服务器在浏览器里留下小纸条，下次访问时带回去。

check_status.py
from urllib.request import urlopen
from urllib.error import HTTPError, URLError

urls = [
    "https://www.example.com",
    "https://www.example.com/404",  # 这个页面不存在
    "https://this-domain-is-not-real-12345.com"
]

for url in urls:
    print(f"\n→ 请求 {url}")
    try:
        with urlopen(url, timeout=5) as resp:
            print(f"  状态码：{resp.status}")
            print(f"  Content-Type：{resp.headers.get('Content-Type')}")
    except HTTPError as e:
        print(f"  HTTP 错误：{e.code} {e.reason}")
    except URLError as e:
        print(f"  网络/解析错误：{e.reason}")

这段代码展示了网络编程的另一条铁律：永远要处理异常。网络请求可能因为断网、DNS 失败、服务器 500 错误而失败，程序必须优雅地处理这些情况。

第 3 小节

HTTPS：给快递箱加把锁

HTTP 有一个明显的问题：数据是明文传输的。如果有人在公共 Wi-Fi 里监听，就能看到你输入的账号密码、搜索内容。为了解决这个问题，出现了 HTTPS：在 HTTP 下面加了一层 TLS/SSL 加密。

你可以把 HTTPS 想象成「给快递箱加锁」：发件人和收件人各有一把钥匙，中间经过的任何人即使截获了包裹，也打不开。这把钥匙就是对称加密密钥，而钥匙怎么安全地送到对方手里，则由非对称加密和数字证书来保证。

💡 关键概念

HTTPS = HTTP + TLS/SSL。TLS 负责加密和身份验证；数字证书由受信任的机构（CA）颁发，证明「这个网站确实是它宣称的那个网站」。

在浏览器里，地址栏出现小锁图标就说明当前网页用了 HTTPS。点击小锁通常能看到证书信息：颁发者、有效期、域名等。

Python 的 urllib 默认会验证 HTTPS 证书。如果你访问一个证书无效的网站，程序会报错。这是好事，说明它在帮你识别假冒网站。下面这段代码展示如何安全地访问 HTTPS 站点：

https_safe.py
from urllib.request import urlopen
from urllib.error import URLError

url = "https://www.python.org"
try:
    with urlopen(url, timeout=5) as resp:
        print("状态码：", resp.status)
        print("URL：", resp.url)  # 如果发生重定向，这里会显示最终地址
        print("\n网页标题附近内容：")
        text = resp.read(500).decode("utf-8")
        print(text)
except URLError as e:
    print("请求失败：", e.reason)
第 4 小节

综合实战：网页状态检查器

批量检查一组网址是否能正常访问

运维和测试工作中经常需要检查一堆网址是否 alive。下面这个 Python 小工具会批量请求一组 URL，输出它们的状态码、响应时间和内容类型。你可以把它扩展成定时运行、发送告警邮件。

url_health_checker.py
from urllib.request import urlopen
from urllib.error import HTTPError, URLError
import time

urls = [
    "https://www.example.com",
    "https://www.python.org",
    "https://httpbin.org/status/500",  # 服务器会返回 500
    "https://httpbin.org/status/404"   # 服务器会返回 404
]

for url in urls:
    start = time.time()
    try:
        with urlopen(url, timeout=5) as resp:
            elapsed = (time.time() - start) * 1000
            print(f"✅ {url}")
            print(f"   状态码：{resp.status}，耗时：{elapsed:.1f}ms")
            print(f"   Content-Type：{resp.headers.get('Content-Type')}")
    except HTTPError as e:
        print(f"⚠️  {url} -> HTTP {e.code} {e.reason}")
    except URLError as e:
        print(f"❌ {url} -> 网络错误：{e.reason}")
    print()

这个练习把模块 3 的核心知识点都用上了：

1. GET 请求：用 urlopen 向服务器要资源。

2. 状态码：根据状态码判断请求是否成功。

3. HTTPS：urlopen 自动处理 TLS 加密和证书验证。

4. 异常处理：HTTPError 和 URLError 分别对应 HTTP 错误和网络/解析错误。

🔑 模块 3 小结

HTTP 是浏览器和服务器之间的请求/响应协议；状态码告诉我们结果；HTTPS 在 HTTP 基础上加密，保护数据不被窃听和篡改。Python 的 urllib.request 足以完成大多数基础网络请求。
