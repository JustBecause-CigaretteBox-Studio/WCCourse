第 1 小节

选题与需求定义

做一个小而完整的网站

本模块的实战目标是：用 AI 帮你从零搭建一个完整的小网站，并部署到互联网上。 为了可控，我们选择做一个功能简单但五脏俱全的项目。

推荐选题：个人作品集主页

原因：不需要后端，只要 HTML + CSS + JS 就能完成； 而且完成后可以直接作为自己的主页展示。

项目需求（MVP）
个人作品集主页：
- 顶部导航：首页、作品、关于、联系
- 首页：一句简介 + 个人头像/占位图
- 作品页：3 个项目卡片，每个包含标题、简介、链接
- 关于页：一段自我介绍
- 联系页：邮箱和社交链接
- 响应式布局，适配手机
- 深色/浅色主题切换（可选）

把需求写成一份完整的 prompt，发给 AI。参考结构：

初始 prompt 模板
角色：你是一名熟悉原生 HTML/CSS/JS 的前端工程师。

目标：帮我做一个个人作品集主页网站。

功能需求：
1. 顶部固定导航，包含首页、作品、关于、联系四个入口
2. 点击导航切换内容，页面不刷新
3. 作品页至少展示 3 个项目卡片
4. 联系页展示邮箱和 GitHub 链接
5. 适配手机浏览

约束：
- 单文件 HTML（把所有 CSS 和 JS 写在同一个文件里）
- 不使用外部框架
- 代码注释用中文
- 风格简洁现代

请输出完整可运行的 HTML 代码。

拿到第一版代码后，先保存为 index.html，双击看看效果。 接下来我们会通过多轮对话迭代优化。

第 2 小节

生成与迭代

把第一版改成可用的样子

第一版代码通常有这些问题：颜色搭配奇怪、手机上看太挤、内容用了太多占位符。 不要灰心，这正是多轮对话发挥作用的时候。

建议的迭代顺序：

迭代计划
第 1 轮：修 bug
- 导航切换是否正常？
- 手机上有没有横向滚动条？
- 图片是否能正常显示？

第 2 轮：改内容
- 把占位文字换成你自己的真实信息
- 把示例项目换成你自己的项目或练习作品

第 3 轮：调样式
- 统一配色（可以用在线工具如 coolors.co）
- 调整间距和字体大小
- 增加 hover 效果和过渡动画

第 4 轮：加小功能
- 深色/浅色主题切换
- 返回顶部按钮
- 简单的表单验证

每轮只聚焦一个主题。例如：

迭代 prompt 示例
请修改当前代码，实现深色/浅色主题切换：
1. 在右上角添加一个切换按钮（太阳/月亮图标或文字）
2. 点击后切换深色和浅色两套 CSS 变量
3. 刷新页面后记住用户的选择（用 localStorage）
4. 默认跟随系统主题

注意：只改样式相关代码，不要动页面结构和导航逻辑。

迭代过程中记得勤保存。每得到一版满意的代码，就复制一份备份， 文件名用 index_v1.html、index_v2.html 这样区分。

第 3 小节

本地验证与常见部署方式

让全世界都能访问你的网站

代码改到满意后，先在本机做最后一轮检查，再部署上线。

如果你实在不懂如何操作，可以暂时跳过这一小节

本地验证清单：

上线前检查
□ 在 Chrome、Edge、Firefox 中打开是否正常？
□ 按 F12 打开开发者工具，Console 有没有红色报错？
□ 手机模式下（浏览器 DevTools 的设备模拟）是否显示正常？
□ 所有链接是否都能点击？
□ 图片和资源路径是否正确？

常见部署方式：

部署选项
1. GitHub Pages（免费，适合静态网站）
   - 把代码推到 GitHub 仓库
   - 在仓库 Settings → Pages 里启用
   - 获得一个 xxx.github.io 的网址

2. CloudStudio / CloudBase（国内访问快）
   - 上传文件到静态网站托管
   - 自动生成访问链接

3. Vercel / Netlify（国外平台，功能强大）
   - 连接 GitHub 仓库自动部署
   - 支持自定义域名

对于我们的个人作品集主页，GitHub Pages 是最简单免费的选择。 如果你已经有 GitHub 账号，整个过程大概 10 分钟。

如果你不想用 GitHub，也可以把 index.html 上传到任何静态托管服务。 只要服务器能返回 HTML 文件，你的网站就能被访问。

部署前的小提示
1. 删除所有测试用的 console.log
2. 检查文件路径是相对路径（./style.css）还是绝对路径（/style.css）
3. 所有图片最好放在项目文件夹里，不要引用可能失效的外部链接
4. 给网页加上 title 和 meta description，搜索引擎更容易找到
第 4 小节

综合实战：发布你的个人作品集主页

从 0 到 1，让网站上线

现在把前面所有模块的内容串起来，完成一个真正的项目： 用 AI 生成、迭代、审查，最后部署一个个人作品集主页。

项目时间表（建议）：

开发计划
第 1 步：写初始 prompt（模块 1 + 模块 2）
- 明确角色、目标、约束
- 让 AI 生成第一版单文件 HTML

第 2 步：多轮迭代（模块 4）
- 修 bug
- 改内容
- 调样式
- 加主题切换

第 3 步：审代码（模块 3）
- 检查 Console 报错
- 让 AI 审查自己的代码
- 测试手机和不同浏览器

第 4 步：整理文件结构（模块 5）
- 虽然现在单文件也能跑，但可以练习拆成 css/style.css 和 js/main.js
- 写一份 README.md

第 5 步：部署上线
- 上传到 GitHub Pages 或其他静态托管
- 把链接分享给朋友

验收标准：

完成检查
□ 网站可以通过一个公开链接访问
□ 手机打开显示正常
□ 导航切换流畅
□ 没有明显的拼写错误和占位内容
□ 源代码有基本注释
□ 你自己能向别人解释网站的每个部分是怎么来的

完成这个项目后，你就体验了一次完整的 Vibe Coding 高阶流程： 不是让 AI 替你写，而是让 AI 在你的导演下，一起完成一个作品。

把最后的发布链接记录下来，它是你学习成果的最好证明。
