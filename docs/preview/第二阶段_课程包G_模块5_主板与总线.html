第 1 小节

主板：所有硬件的「骨架」

主板是一块大型印刷电路板（PCB），CPU、内存、显卡、硬盘、电源等所有部件都插在它上面。它不提供算力，但负责让各个部件互相连接、互相通信。

主板上还有很多辅助芯片，比如芯片组（Chipset）负责协调 CPU 与外设之间的数据交换，BIOS/UEFI 芯片负责开机自检和引导操作系统。你可以把主板想象成城市的道路网：它自己不运货，但没有它，货就没法运。

第 2 小节

总线：数据的高速公路

主板上的各种部件要靠总线（Bus）来传输数据。总线就像高速公路，负责把信息从一个地方运到另一个地方。常见的总线分为三类：

  • 数据总线（Data Bus）：运送实际的数据，比如从内存读到 CPU 的一个数。
  • 地址总线（Address Bus）：运送内存地址，告诉对方「我要读写哪个位置」。
  • 控制总线（Control Bus）：运送控制信号，比如「读」「写」「准备好没有」等命令。

总线有宽度限制。地址总线的宽度决定了 CPU 能访问多少内存：32 位地址总线最多访问 2³² 字节，约 4 GB；64 位地址总线则能访问极大的空间。数据总线的宽度则决定了一次能搬运多少位数据。

第 3 小节

带宽与延迟：总线有多快

衡量总线性能有两个关键指标：

  • 带宽（Bandwidth）：单位时间内能传输多少数据，通常用 GB/s 表示。带宽越高，同时传输的数据越多。
  • 延迟（Latency）：从发出请求到收到第一个数据需要多少时间，通常用纳秒（ns）或毫秒（ms）表示。延迟越低，响应越快。

打个比方：带宽像高速公路的车道数量，延迟像从入口到出口的行驶时间。车道再多，如果路很长、红绿灯很多，第一次到达仍然慢。

计算总线带宽
# 假设总线宽度 64 位，频率 1 GHz
bus_width_bits = 64
frequency_hz = 1000000000   # 1 GHz = 10 亿 Hz

# 每秒传输字节数 = 位宽 × 频率 / 8
bandwidth_bytes_per_sec = bus_width_bits * frequency_hz / 8
bandwidth_gb_per_sec = bandwidth_bytes_per_sec / 1000000000

print("理论带宽:", bandwidth_gb_per_sec, "GB/s")

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    // 假设总线宽度 64 位，频率 1 GHz
    int bus_width_bits = 64;
    double frequency_hz = 1000000000;   // 1 GHz = 10 亿 Hz

    // 每秒传输字节数 = 位宽 × 频率 / 8
    double bandwidth_bytes_per_sec = bus_width_bits * frequency_hz / 8;
    double bandwidth_gb_per_sec = bandwidth_bytes_per_sec / 1000000000;

    // fixed + setprecision(2)：让小数只保留两位（格式控制，记住这个写法即可）
    cout << fixed << setprecision(2);
    cout << "理论带宽: " << bandwidth_gb_per_sec << " GB/s" << endl;
    return 0;
}

现代电脑里，CPU 和内存之间有高速总线（如 DDR 内存通道），显卡通过 PCIe 总线连接，硬盘通过 SATA 或 NVMe 总线连接。NVMe 比 SATA 快很多，正是因为它的总线更宽、协议更高效。

第 4 小节

综合实战：模拟总线传输

用 Python 体验带宽与延迟

下面我们写一个简化版总线模拟器：CPU 要从内存读取一批数据。你会看到，即使「总线带宽」很高，如果每次读取都要等待较长的「延迟」，总耗时也会显著增加。

总线传输模拟
def read_from_memory(data_size_mb, bandwidth_gb_s, latency_ms):
    # data_size_mb: 要读的数据大小（MB）
    # bandwidth_gb_s: 总线带宽（GB/s）
    # latency_ms: 每次访问的延迟（ms）

    # 传输时间 = 数据量 / 带宽
    transfer_time_s = (data_size_mb / 1024) / bandwidth_gb_s
    latency_s = latency_ms / 1000
    total_s = latency_s + transfer_time_s
    return total_s

# 对比两种总线（按顺序传入三个参数：数据量、带宽、延迟）
slow = read_from_memory(100, 0.5, 10)
fast = read_from_memory(100, 10.0, 0.1)

print("慢总线（SATA 硬盘风格）:", round(slow, 3), "秒")   # round(x, 3) 保留三位小数
print("快总线（NVMe 硬盘风格）:", round(fast, 3), "秒")
print("快总线约是慢总线的", round(slow / fast, 1), "倍")
bus_simulator.cpp
#include <iostream>
#include <iomanip>
using namespace std;

// data_size_mb: 要读的数据大小（MB）
// bandwidth_gb_s: 总线带宽（GB/s）
// latency_ms: 每次访问的延迟（ms）
double read_from_memory(double data_size_mb, double bandwidth_gb_s, double latency_ms) {
    double transfer_time_s = (data_size_mb / 1024.0) / bandwidth_gb_s;
    double latency_s = latency_ms / 1000.0;
    return latency_s + transfer_time_s;
}

int main() {
    double slow = read_from_memory(100, 0.5, 10);
    double fast = read_from_memory(100, 10.0, 0.1);

    // fixed + setprecision(3)：让小数只保留三位（格式控制，记住这个写法即可）
    cout << fixed << setprecision(3);
    cout << "慢总线（SATA 硬盘风格）: " << slow << " 秒" << endl;
    cout << "快总线（NVMe 硬盘风格）: " << fast << " 秒" << endl;
    cout << "快总线约是慢总线的 " << slow / fast << " 倍" << endl;
    return 0;
}
💡 扩展挑战

把上面的函数改成「每次只能读取 4 KB 的小块」，并且每次读取都要付一次延迟。对比「一次读取 100 MB」和「分 25600 次读取 4 KB」的总时间，体会为什么减少请求次数、合并数据访问能提升性能。
