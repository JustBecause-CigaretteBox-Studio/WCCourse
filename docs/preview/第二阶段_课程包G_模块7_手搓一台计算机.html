第 1 小节

整机蓝图：把零件摆上桌子

先看清一台计算机由哪几块拼成

模块 1 到模块 5，我们分别认识了 CPU 内部的大脑（运算、取指令）、内存与硬盘（记住东西）、显卡（画画面）、主板与总线（把它们连起来）。现在把它们全部摆在一张图里，你就看到一台计算机的「全家福」了。

这张图里最关键的不是某块有多大，而是那三根连在 CPU 和内存之间的「总线」。它就像一条公共马路：数据要走它、地址要走它、控制信号也要走它。CPU 想从内存拿一个数，就往总线上喊一声「地址 3 的数据给我」，内存回应「这是数据」，数据再沿总线回到 CPU。后面三节，我们就把这条马路和马路两头的房子一件件做出来。

第 2 小节

寄存器与内存：红石怎么记住一个数

从「1 个比特」到「1 个字节」

前面模块 6 里，拉杆一扳代表 1、扳回去代表 0。但拉杆会「忘」——你一走开，它还是 1 还是 0 全看现场。计算机需要的是：一旦写入，就一直保持，直到被新数据覆盖。红石里有专门的「锁存」元件能记住状态，对应现实里的寄存器与内存。

上图是内存里最小的一格「字节」：8 个小灯（比特）排成一排，能表示 0 到 255 之间的任意整数。寄存器就是 CPU 内部的小而快的这种格子（比如 32 位寄存器 = 32 个比特一排）；内存则是成千上万个这样的格子排成一面墙，每个格子有一个编号（地址）。我们用一段代码模拟「在寄存器里存一个数、再读出来」：

用 Python 模拟一个 4 位寄存器
# 寄存器 = 一串会记住自己的比特
reg = [0, 0, 0, 0]          # 4 个比特，初始全为 0

def write(value):            # 把 0~15 的数写进寄存器
    for i in range(4):
        reg[3 - i] = (value >> i) & 1

def read():                  # 从寄存器读出这个数
    return sum(bit << (3 - i) for i, bit in enumerate(reg))

write(9)                     # 9 的二进制是 1001
print(reg)                   # [1, 0, 0, 1]
print(read())                # 9
register.cpp
#include <iostream>
using namespace std;

int main() {
    int reg = 0;             // C++ 里一个 int 就是一排会记住自己的比特

    reg = 9;                 // 9 的二进制是 1001
    cout << reg << endl;    // 9

    reg = reg << 1;          // 左移一位：相当于把所有比特往左挪，变成 10010 = 18
    cout << reg << endl;    // 18
    return 0;
}

现实中你不用自己一个比特一个比特去拨——编译器会帮你把 reg = 9 翻译成「把对应那几个比特点亮」的动作。但理解「数据其实是被记住的一排 0/1」，是看懂计算机的第一步。

第 3 小节

控制单元与时钟：让计算机「一步步」动起来

没有指挥，零件只是一堆静止的红石

有了寄存器和 ALU，零件齐了，但它们还不会自己动。你需要一个「指挥家」——控制单元，外加一只不停打拍子的时钟。时钟每「滴答」一次，控制单元就指挥大家做一步：先从内存取一条指令，再交给 ALU 算，最后把结果写回寄存器或内存。然后滴答第二下，再来一轮。

这「取指令 → 执行 → 取指令 → 执行」的循环，就是传说中的取指-执行周期（Fetch-Decode-Execute Cycle）。下面用代码模拟这一节奏：一个 while 循环，每轮先取一条、再执行一条，直到程序结束。

用 Python 模拟取指-执行循环
program = ["LOAD 5", "ADD 3", "STORE 0"]   # 一条小程序：载入5、加3、存回
regs = [0, 0, 0, 0]

pc = 0                       # pc = 程序计数器，指向当前指令
while pc < len(program):
    instr = program[pc]      # ① 取指令
    print("执行:", instr)    # ② 执行（这里简化为打印）
    pc = pc + 1              # 指向下一条，等下一个时钟滴答
cycle.cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    vector<string> program = {"LOAD 5", "ADD 3", "STORE 0"};
    int pc = 0;                       // pc = 程序计数器

    while (pc < program.size()) {
        string instr = program[pc];   // ① 取指令
        cout << "执行: " << instr << endl;   // ② 执行
        pc = pc + 1;                  // 等下一个时钟滴答
    }
    return 0;
}

时钟越快，每秒能跑的循环就越多——这就是你买电脑时关心的「主频 3 GHz」的含义：每秒大约 30 亿个滴答。滴答之间，上面那一套取指-执行就完整走一遍。

第 4 小节

连起来：数据总线与整机运行

把 CPU、内存、硬盘串成一条街

最后一步，是用总线把 CPU、内存、硬盘这三家连成一条街。总线就是一排并排的电线：有的专门传「数据」（今天搬什么数），有的专门传「地址」（搬到哪个格子），有的专门传「控制」（是读还是写）。谁要在总线上说话，先举手申请，总线空闲了再发。这样所有零件共用一条马路，省去两两之间拉专线的麻烦。

把这一节到第一节连起来看：拉杆（模块 6 的红石）→ 逻辑门 → 加法器 → 寄存器 → 时钟指挥 → 总线串起 CPU 和内存。从课程包 G 模块 1 的一颗灯泡，到这一节的一整台计算机，红石依然是那同一种「通电 / 断电 = 1 / 0」的游戏。你在《我的世界》里搭出来的，本质上就是真实 CPU 的工作原理的玩具版。

💡 收尾一句话

计算机不是魔法，它只是无数个「会翻转的开关」被时钟一点点组织起来，按写在内存里的指令，自动完成你交给它的事。看懂了这台红石计算机，你就看懂了模块 1 里那颗芯片的灵魂。
